# file-browser 规格增量

## ADDED Requirements

### Requirement: 会话文件链接在 Web 端只读查看

会话页面上展示的文件链接被点击时，客户端 SHALL 在 Web 端的文件浏览器对话框内以只读方式呈现该文件内容，而不是调用 Host 桌面打开器。该行为在 Host 无桌面环境、以及浏览器与 Host 不同机时同样成立。

#### Scenario: 点击会话中的文件链接
- **WHEN** 用户点击会话页面里某个已编辑或新增文件的链接
- **THEN** 客户端打开文件浏览器对话框
- **AND** 对话框直接呈现该文件的内容
- **AND** 内容区处于只读态，不提供保存、覆盖与重载动作

#### Scenario: 云端部署下查看文件
- **WHEN** 部署在无桌面环境的 Host 上，用户点击会话中的文件链接
- **THEN** 文件内容仍在浏览器中呈现
- **AND** 该过程不依赖 Host 的桌面打开器

### Requirement: 会话到工作区的解析

客户端 SHALL 由会话身份反查其所属工作区，并把该工作区作为文件读取的范围。反查不到工作区时客户端 SHALL 给出明确提示，且 SHALL NOT 回退到 Host 桌面打开器。

#### Scenario: 会话属于某个工作区
- **WHEN** 用户点击的链接来自一个已登记到工作区的会话
- **THEN** 客户端以该工作区为范围发起读取

#### Scenario: 会话未登记到任何工作区
- **WHEN** 点击的链接来自一个反查不到工作区的会话
- **THEN** 客户端提示无法查看该文件
- **AND** 不调用 Host 桌面打开器

### Requirement: 只读是入口的属性

同一文件经工作区浏览器入口打开时可编辑，经会话文件链接入口打开时 SHALL 只读。只读态 SHALL 保留语法高亮与复制。

#### Scenario: 经会话链接打开文本文件
- **WHEN** 一个文本文件经会话文件链接打开
- **THEN** 内容以语法高亮呈现
- **AND** 不提供保存与覆盖动作

#### Scenario: 经工作区菜单打开同一文件
- **WHEN** 同一文件经工作区行菜单的文件浏览器打开
- **THEN** 内容仍可编辑并保存

### Requirement: 本地编辑器入口作为次要动作

查看器 SHALL 仅当连接为 loopback 且 Host 报告具备桌面打开能力时，才提供「用本地编辑器打开」入口。目录路径 SHALL 继续经 Host 桌面打开器处理。

#### Scenario: 本地且 Host 具备打开能力
- **WHEN** 连接为 loopback 且 Host 报告可打开工作区路径
- **THEN** 查看器显示「用本地编辑器打开」入口
- **AND** 点击后调用 Host 桌面打开器

#### Scenario: 云端或 Host 无打开能力
- **WHEN** 连接非 loopback，或 Host 报告不具备打开能力
- **THEN** 查看器不显示该入口

#### Scenario: 目录路径
- **WHEN** 用户触发「在文件夹中显示」这类目录动作
- **THEN** 客户端调用 Host 桌面打开器
- **AND** 不以文本查看方式打开

### Requirement: 超出上限与不可文本查看的内容明确降级

内容为二进制或超过配置上限时，查看器 SHALL 明确提示该事实，而不是呈现截断的部分内容。

#### Scenario: 超过上限的文件
- **WHEN** 打开的文件超过配置的字节上限
- **THEN** 查看器提示文件超出上限并说明上限
- **AND** 若本地编辑器入口可用则仍然提供

#### Scenario: 二进制文件
- **WHEN** 打开的文件不是 UTF-8 文本
- **THEN** 查看器提示无法以文本查看
