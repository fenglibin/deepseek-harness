## 3. 新包结构

- src/types.ts：仅类型（仓库约定）。`ImageDescriberRoute { provider; model; instruction }`。
- src/index.ts：抽象 Service Definition `ImageUnderstanding extends Service`（服务名 'imageUnderstanding'，declare module 增补 Context），成员：只读 `route: ImageDescriberRoute | undefined`（本次部署是否可描述）与 `describe(refs, signal?)`，返回与入参等长、下标对齐的数组，`undefined` 表示该图无描述（合法返回值，调用方回退占位符）；抛错只留给配置错误。
  同文件提供 LLM-backed Service Provider `LlmImageUnderstanding extends ImageUnderstanding` 并 default 导出（照 attachment-local 先例）。Config 字段：provider（默认 ''）、model（默认 ''）、instruction（默认一段版本化提示词，要求客观描述画面并转录可见文字）、maxOutputTokens（默认 512）、timeoutMs（默认 30_000）、maxDescriptionChars（默认 4000）、requestImagePixelBudget / requestImageMaxBytes（描述用压缩策略，默认复用 1024*1024 与 1MiB）、maxCacheEntries（默认 64）。构造函数校验正整数与成对约束，违反即抛（fails loud）。
  route 解析：provider/model 均非空 → 直接用；均空 → 从 ctx.llm.listModels() 选第一条 inputModalities 含 image 的模型并 logger.info 记录选择；都没有 → route 为 undefined。首次 describe 时校验该路由的 inputModalities 必须含 image，否则抛错（这里是唯一该抛错的地方）。
  describe 流程：缓存命中（key = attachmentId + route + instruction）直接返回；否则 ctx.attachments.readImageRequest(ref, policy, signal) 取压缩图 → createUserMessage 组装 [image 块, instruction 文本块]，source 为 { kind:'plugin', plugin: '@deepseek-ai/dsh-image-understanding' } → ctx.llm.stream({ provider, model, messages, maxTokens, purpose:'image-understanding', signal }) + BlockAssembler（与 compaction-basic summarizer 同一写法）→ finish 出错则抛 → 取首个 text 块、trim、按 maxDescriptionChars 截断 → 写入缓存。失败/超时/取消向上抛，由 Consumer 降级。
- src/consumer.ts：导出 `describeForRoute(ctx, refs, route, signal?)`。判定顺序：路由支持 image（inputModalities 未声明或含 image）→ 返回全 undefined；ctx.get('imageUnderstanding') 缺失 → 全 undefined；否则调用 service.describe 并把异常降级为全 undefined + logger.warn。这是「是否需要描述」的唯一判定处。
- src/invariant.ts：空 installer，给出真实理由（本服务不拥有事件关系，可描述性由 llm 目录校验）。
- package.json / tsconfig.json：照 lightweight-model 与 attachment-local 的脚手架；依赖 dsh-llm、dsh-attachment、schemastery、cordis、dsh-invariants。

## 4. session-controller 改动（packages/api/session-controller/src/commands.ts）

- prompt() 的 hasImage 分支：路由为纯文本时，仅当 `ctx.get('imageUnderstanding')` 缺失才抛既有 `session/attachment-invalid` + `MODEL_DOES_NOT_SUPPORT_IMAGES`；有描述器则放行。错误文案与码保持不变（客户端 attachmentErrorText 依赖它们）。
- durablePromptContent 增加 route 入参：在 admitEncodedImages 之后调用 describeForRoute，把返回的 description 按序挂到每个 image 块上（无描述则不加字段）。描述调用发生在 agents.serializeImageAdmission 序列化区内，避免并发准入重复触发。
- 用窄接口（只声明 route）对 ctx.get 结果做类型收敛，不引入对新品包的运行时导入以外的耦合；consumer 的 helper 为值导入，记入 package.json dependencies。
