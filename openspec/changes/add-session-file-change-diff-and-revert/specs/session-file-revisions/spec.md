# 会话文件修订的查看与撤销

## 新增能力

会话记录每个被改动文件的基线与末态，使其在网页中可查看累积差异、可撤销；并行子代理的改动归入所属会话，撤销只移除该会话的改动。

### Requirement: 累积差异只覆盖本会话的改动

系统 SHALL 把一个文件的累积差异定义为「会话首次改动前的内容 → 会话最后一次改动后的内容」，且 MUST NOT 把会话之外的改动（用户编辑、其它会话的改动）计入该差异。

#### Scenario: 展示单个文件在会话中的变更

- **WHEN** 用户在「修改的文件」中点击某文件的「查看变更」
- **THEN** 系统展示该文件的基线到末态的差异，且差异中不包含任何非本会话产生的改动

#### Scenario: 文件在会话期间被外部修改

- **WHEN** 某文件在本会话被改动后，其内容又被本会话之外的来源修改
- **THEN** 该文件展示的差异仍然是「会话启始态 → 会话末态」，外部改动不出现在差异中

#### Scenario: 子代理的改动归入所属会话

- **WHEN** 一个子代理会话改动了文件
- **THEN** 该改动出现在其根会话的变更列表中，且父子同改一个文件时基线取更早者、末态取更晚者

### Requirement: 撤销只移除本会话的改动

系统 SHALL 提供撤销，把本会话的改动从文件当前内容中移除，且 MUST 保留其它来源的改动；无法无歧义还原时 MUST 报告冲突而非猜测写入。

#### Scenario: 撤销保留外部改动

- **WHEN** 用户撤销某会话的改动，且该文件此后被本会话之外的来源修改过其它位置
- **THEN** 本会话的改动被还原，外部改动保留在结果中

#### Scenario: 同一处被会话与外部同时改动

- **WHEN** 用户撤销，且本会话改动的那部分内容此后被覆盖
- **THEN** 系统报告冲突并保持文件原样，不写入任何猜测结果

#### Scenario: 部分可还原

- **WHEN** 一个文件的多个改动位置中仅有一部分此后被覆盖
- **THEN** 仍可无歧义还原的部分被还原，其余报告为冲突

#### Scenario: 撤销全部文件

- **WHEN** 用户执行全部撤销
- **THEN** 系统逐个文件应用，成功的生效，失败的按文件报告原因且不中断其余文件

#### Scenario: 撤销会话新建的文件

- **WHEN** 撤销一个由本会话创建的文件
- **THEN** 仅当文件内容仍是本会话写入的那一刻才删除；内容已被他人改写时报告冲突而非删除

### Requirement: 大文件保持可撤销

系统 SHALL 对超过显示上限的内容拒绝下发差异预览，且 MUST 保留其基线使其仍可撤销。

#### Scenario: 内容超过显示上限

- **WHEN** 某文件的内容超过配置的显示上限
- **THEN** 系统提示无法预览而不下发正文，但该文件的撤销仍然可用

### Requirement: 接受与撤销是两种不同的操作

系统 SHALL 保留既有的「接受」行为（界面层面的隐藏，不动磁盘），并 MUST 使其与「撤销」（真还原文件）在界面上明确区分。

#### Scenario: 接受不改变磁盘

- **WHEN** 用户接受一个文件
- **THEN** 该文件从待处理列表移除，磁盘内容不变，且该文件再次被改动后重新出现

### Requirement: 能力缺席时界面降级

系统 SHALL 在未装配修订捕获时隐藏「查看变更」与「撤销」，且 MUST 保持变更列表与接受功能不变。

#### Scenario: 未装配修订捕获

- **WHEN** 组合中未挂载修订捕获插件
- **THEN** 变更列表正常显示但不含查看变更与撤销控件，接受功能照常工作

### Requirement: 撤销的写盘边界

系统 MUST 仅在解析出会话自身工作区根、并确认目标路径位于该根之内后才写盘。

#### Scenario: 记录的路径指向工作区之外

- **WHEN** 撤销的目标路径经解析后位于工作区之外（例如捕获之后放置的符号链接）
- **THEN** 系统拒绝写盘并报告失败，不写任何文件
