# 查看变更改为全屏并排 diff

## 为什么

「查看变更」目前把一块统一格式（unified）的 `DiffBlock` 渲染在输入框上方的 dock 条带里。三个问题：条带空间太窄，默认 16 行后就折叠中部；统一格式把删除与新增分列两处，读者要在脑中重建「这一行变成了那一行」；没有行号也没有语法高亮，长文件里定位改动只能靠肉眼扫。

用户提出三条要求：变更要弹出新页面展示、用左右栏并排方式对照、体验参考 git。

## 改什么

1. **触发与承载分离**：dock 的「查看变更」不再渲染 diff，而是发布一个打开请求；新增的 `shell.overlay` 条目（root 作用域的 list 槽位）订阅该请求并渲染全屏视图。两者经 `apply` 闭包内的一个共享 observable 连接——这与仓库既有的「文件浏览器」同构，是已被验证的、让 session 作用域的触发方驱动 root 作用域承载方的方式。
2. **并排对齐模型**：把 `structuredPatch` 的行序列折叠成 `[left, right]` 行对——相邻连续删除行与连续新增行按序配对，第 i 删与第 i 增占用同一行；一侧多出的部分补空占位，因此两栏始终等高、行号对齐。这是 split view 与「重新排版过的 unified diff」的本质区别。
3. **完整 git 体验**：两侧行号、shiki 语法高亮（复用既有单例，懒加载语法不阻塞）、变更行背景、行内字符级差异高亮、长行横向滚动且两栏同步、上一处/下一处变更跳转与位置读数。
4. **复制仍输出标准 diff**：复制的是 `-`/`+` 统一格式文本，不是屏幕上的两栏布局——粘进终端或 patch 文件必须仍是合法 diff。
5. **只读评审面**：查看器不提供撤销；撤销仍留在能看到全部文件的 dock 上，避免同一破坏性动作有两个所有者。

## 影响

- `ui-session-changes` 新增并排模型、查看器组件、请求源与覆盖层注册；删除内联面板；新增 `diff` 与 `clsx` 运行时依赖。
- `ui-primitives` 新增共享的文件扩展名到语言映射，并让 `ui-file-browser` 改为复用它——消除原本两处必须永远一致的重复表。
- Host 侧、Remote 契约、会话日志与录制快照均不变。
- 既有 `DiffBlock` 不动：它继续服务会话内的工具调用卡片。
