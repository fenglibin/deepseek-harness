# @deepseek-ai/dsh-client-ui-file-browser

## 概述

本包把两个贡献挂进 Web GUI：一个工作区行「...」菜单里的**文件浏览器**条目，以及一个挂在 `shell.overlay` 上的文件管理器弹层。弹层有两种形态，由打开意图决定：浏览器形态左侧是工作区目录的懒加载树（含文件名搜索、新建、重命名、删除），右侧是选中文件的内容区；文件形态只呈现那一个文件，只读。两种形态下文本都带按扩展名解析的 shiki 语法着色，Markdown 与 HTML 默认以渲染后的预览呈现、可切回源码；图片用 `<img>` 查看；二进制与超过大小上限的文件给出明确提示而不进编辑器。所有磁盘操作都经由 Host 的 `fileBrowser` Remote（[`dsh-api-file-browser`](../../api/file-browser/README.zh.md)）。

它同时通过 `ctx.fileViewer` 向兄弟插件提供只读查看入口，会话页面里的文件链接由此在浏览器中打开，而不依赖 Host 的桌面打开器。

<a id="use-this-package"></a>
## 使用本包

把本插件与 `dsh-api-file-browser`、`ui-workspace` 一起挂载即可。它出现在组合里之后，每个真实工作区行的菜单就多出**文件浏览器**一项；Ungrouped 分桶没有菜单，因此也没有该条目。

### 浏览器形态的两列

弹层顶部是**一行**工具栏，从左到右依次是标题、按文件名搜索、隐藏项开关、新建文件与新建文件夹、关闭。搜索框是这一行里唯一可伸缩的控件（其余保持自身宽度），所以窄窗口下也不会折行——把它们堆成多行会把树往下挤，而每一行并不多说任何事。

左列是工作区根目录的树。每个目录在**首次展开时**才列举一层，折叠不会丢弃已取回的层，所以重新展开是即时的。默认隐藏点开头的条目与 `node_modules`、`.git`、`dist` 等重目录，工具栏上的**隐藏项**开关会重新从根目录开始取。列举在 Host 的条数上限处截断时会明确说明。工具栏的搜索输入片段后，树被一份扁平结果列表取代，点击结果会展开其祖先目录并打开该文件。搜索只匹配名称，不匹配内容。

右列由文件读取回来的分支决定：文本进编辑器，图片用 `<img>` 呈现，二进制与超限文件各给出自己的提示，读取失败另有一行提示。

弹层尺寸是布局状态而非持久偏好：拖右下角抓手可同时改宽高，拖两列之间的分隔条可重新分配树的宽度，两者都直接改写 CSS 自定义属性（`--dsl-fb-width`、`--dsl-fb-height`、`--dsl-fb-side`）——拖动每帧都触发 pointermove，把这三次写进 React state 会让整棵树与编辑器跟着重渲染。尺寸在视口与各自的最小可用宽高处收敛，刷新页面回到样式表给出的初值，因为一个记下来的宽度在另一块屏幕上会落错位置。

### 文件形态：只在浏览器里看一个文件

会话页面里的文件链接（来自 chat 的产物提及、会话变更列表、交付卡片）经 `ctx.fileViewer.open({ sessionId, path })` 打开这一形态。门面按会话所属工作区发起读取，因此链接在 Host 没有桌面环境、或浏览器与 Host 不是同一台机器时同样可用。该形态不显示目录树、搜索、隐藏项开关与新建按钮：它要呈现的就是那一个文件。

只读是**入口**的属性，不是文件的属性：同一个文件从工作区菜单打开仍可编辑保存，从会话链接打开则隐藏保存、重新加载与强制覆盖，只保留语法高亮与复制。

超过 `maxFileBytes` 的文件与二进制文件仍给出各自的提示，并附上**用本地编辑器打开**——该入口只在页面就位于 Host 自身（loopback）且 Host 报告具备桌面打开能力时出现。目录动作（产物行的「在文件夹中显示」）不走此形态，它继续交给桌面打开器。

会话反查不到所属工作区时（例如子代理会话，或 cwd 未登记）弹层给出明确提示，**不会**回退到桌面打开器。

### 编辑器

编辑器是上层透明 `<textarea>` 叠在下层只读高亮层之上，两层共用字体、行高与内边距，所以光标落在字上。着色按扩展名解析语言，覆盖常见的后端与前端语言以及 JSON、YAML/YML、XML、TOML、INI、HTML、CSS、Markdown；无法识别的扩展名回退为纯文本，仍可编辑保存。着色器是 `ui-primitives` 里那个唯一的 shiki 单例，颜色取自 `--shiki-*` 主题变量。

`textarea` 关闭了软换行（`wrap="off"`）：高亮层按源码行渲染，一行一行对应，软换行会让文字落在高亮层从不绘制的位置，两层就此错位，而且长行永远不溢出、横向滚动条也就不出现。代价是长行需要横向滚动查看。

编辑器占满右列的高度，行数超出时由内层滚动容器出纵向滚动条，列宽超出时出横向滚动条。

`Ctrl+S`（macOS 为 `Cmd+S`）保存，工具栏上也有保存按钮；缓冲区与磁盘内容不一致时显示未保存标记。保存携带读入时的版本令牌，磁盘上的文件若已被其它程序改动，保存会以冲突被拒绝，并给出**重新加载**与**强制覆盖**两个选择——前者重新读取磁盘内容，后者不带版本令牌写入。

内容区的工具栏只有一行：路径、保存状态、预览开关（仅可预览的文件有，默认勾选）、重新加载与保存。搜索框与这两个动作按钮都取与相邻文字同级的 13px/12px，而不是共享 `Input` 与 `Button` 原子的默认尺寸——那一行是密集工具栏，不是表单。

### 预览 Markdown 与 HTML

扩展名为 `.md`、`.markdown`、`.html`、`.htm` 的文件在内容区工具栏有**预览**开关，其余文件没有该控件。**这类文件打开时默认就在预览态**：打开一份 Markdown 或 HTML，要看的本来就是渲染结果，源码因此改为按需切回。取消勾选回到编辑器并**保留未保存的修改**：两种视图共用同一份缓冲区，预览渲染的就是缓冲区当前内容，因此没保存的改动也能看到效果。这也意味着预览期间不提供保存与重新加载——它们是编辑动作，回到编辑器即可。

默认只描述「打开」这一个动作：切换文件时按新文件重新取默认值（可预览→预览，其余→编辑器），而重新加载当前文件留在操作者所在的视图里，不会被默认值拉回预览。

Markdown 走本仓唯一的 Markdown 管线（`ui-primitives` 的 `MarkdownText`），因此表格、任务列表、删除线、脚注、KaTeX 数学与 ```mermaid 流程图都按对话里同样的方式渲染。HTML 无法走那条管线——文件本身就是一份文档，因此交给浏览器自己的解析器：内容是 `srcDoc`，框架带 `sandbox="allow-scripts"`。不给 `allow-same-origin`，文档因此落在不透明源上，脚本仍可运行（产出 HTML 常靠脚本渲染自己），而 `localStorage`、Cookie 与同源 `/api` 请求都不可达。

框架的底色是**文档自己的白纸**而不是当前主题的表面：产出 HTML 通常不声明颜色，UA 样式表因此给它黑字，用深色主题的表面去填就会让黑字压在深底上不可读。文档保持文档的底色，周围的界面仍然表明当前主题。

这一能力落在 `CodeEditor` 上，因为工具栏与状态标记归它所有；浏览器形态与文件形态渲染的是同一个 `CodeEditor`，所以从会话文件链接打开的只读查看器拿到完全相同的预览，不需要第二套实现。

### 树上的文件操作

工具栏的新建文件与新建文件夹落在**当前选中的目录**里：选中某个目录即表示「在这里新建」，选中文件则落在它所在目录，什么都没选中才落在根目录。每个条目悬停时有重命名与删除；新名称必须是单个非空路径片段。删除先经过一次确认，文案指明目标名称并说明该操作不可恢复，取消则什么都不会发生。

### 卸载

菜单条目、弹层注册、`ctx.fileViewer` 门面与 Host 侧的 Remote 贡献都随插件 fiber 生命周期生效。销毁本插件会一并移除它们，不留可点击的死入口；消费方以「门面缺席」为关态，此时会话文件链接回到桌面打开器。

<a id="model-experience"></a>
## 模型体验

无，因为这是运维人员直接操作文件的管理界面：它不注册提示词、工具或会话事件，也不改变任何模型请求。

#### KV Cache 影响

无直接影响；通过该界面查看或编辑文件不会改变模型请求。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- 编辑器提供语法着色，但不提供自动缩进、括号匹配与多光标：它是 textarea 叠加高亮层，不是完整的代码编辑器。
- 语言只由扩展名决定，界面上没有语言选择器。
- 预览类型同样只由扩展名决定：没有扩展名的文件（如 `Makefile`、`.gitignore` 之外的常见形态）不提供预览开关，也没有手动指定类型的入口。
- 预览是切换而非分栏：勾选期间不能编辑，要改 Markdown 或 HTML 就得先取消勾选（缓冲区会保留）。这两类文件默认进入预览，所以编辑它们比编辑其它文本多一步取消勾选。
- 默认视图只按扩展名决定，没有「记住上次选择」的偏好：每次打开可预览文件都从预览开始。
- HTML 预览取的是文档文本本身，不是工作区目录里的一个文件：文档内相对的 `<img>`、`<link>`、`<script src>` 按宿主页面的地址解析，因此加载不到同目录的同级文件，只有绝对地址或内联内容才生效。
- 没有文件监视，磁盘上的外部改动不会自动反映到已打开的文件；只有保存冲突与手动重新加载会让它进入视图。
- 一次只打开一个文件，没有多标签页。
- 查看器一次性读取整个文件，没有分页：超过 `maxFileBytes`（默认 2 MiB）的文件只给出提示与桌面打开入口，而不是部分内容。
- 树列的宽度固定，不可拖拽调整。
- 没有文件内容检索，也没有下载入口。

### 开发备注

<details>
  <summary>维护者工作上下文——点击展开</summary>

`apply` 内的注册共享一个闭包持有的「打开请求」源：菜单项把被点击的工作区推入，门面把会话文件推入，弹层订阅它并渲染对话框。该状态既不需要跨重挂载存活（不入 store），也不能是模块级单例（`apply` 是唯一合法的创建点），因此放在闭包里。请求是判别联合，所以「浏览工作区却只读」这种组合不可表达。对话框是唯一持有服务端状态的地方——树渲染被交给它的层，编辑器渲染被交给它的缓冲区——所以新建、重命名、删除各自该刷新哪一层都只有一处实现。

会话到工作区的映射由门面独占：`WorkspaceView.sessionIds` 已把每个会话登记到其工作区，因此用现有 `ctx.workspaces` 快照反查即可，不需要新的 Host 协议面。反查不到时发布一个 `unavailable` 请求臂，让提示与「不回退桌面打开器」这条规则只有一处实现。

预览落在 `CodeEditor` 而不是新增一个内容区组件：工具栏（路径、保存状态、写动作）与冲突横幅都归它所有，独立预览组件会把这三样各复制一份。两种视图共用同一个缓冲区，所以取消勾选能拿回未保存的修改，取消勾选也不需要任何回写动作。HTML 用 `srcDoc` + `sandbox="allow-scripts"`：给文档一个不透明源，是让脚本能跑、同时够不到宿主页面的最小授权；完全禁脚本会让靠脚本渲染的产出 HTML 变成死页面，而那种破坏是看不见的。

</details>
