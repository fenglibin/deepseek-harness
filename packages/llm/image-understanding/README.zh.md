# @deepseek-ai/dsh-image-understanding

## 概述

本包为无法接收图片的模型路由提供图片的文字说明。当提交的消息包含图片、而所选路由声明只接受文本输入时，本包会请求一条具备视觉能力的模型路由为每张图片生成描述，并把结果附加到持久化的图片块上，这样目标模型随后读到的是长度受限的文字，而不再是"图片被省略"的提示。已经支持图片的路由不受影响：它照常收到压缩后的请求图片，本包不会发起任何描述调用。没有任何具备图片能力模型的部署，其行为与过去完全一致，因为描述器不可用时只是没有描述，而不是报错。

<a id="use-this-package"></a>
## 使用本包

挂载本插件即可；除非部署环境中第一个支持图片的模型恰好不是合适的描述器，否则再显式指定视觉路由。除此外无需其他配置：只有目标路由确实需要时，准入路径才会去取描述。

### 最小配置

```yaml
- name: '@deepseek-ai/dsh-image-understanding'
```

| 字段 | 默认值 | 含义 |
|---|---|---|
| `provider` | `''` | 描述模型的 provider 路由；留空则自动选择第一个声明支持图片输入的已注册模型 |
| `model` | `''` | `provider` 上的模型 id；必须与 `provider` 同时设置 |
| `instruction` | 带版本的默认值 | 随每张图片一起发送的指令；属于路由标识的一部分 |
| `maxOutputTokens` | `512` | 单条描述的输出 token 上限 |
| `timeoutMs` | `30000` | 单次理解调用的端到端超时时间 |
| `maxDescriptionChars` | `4000` | 单条描述保留的字符数 |
| `requestImagePixelBudget` | `1048576` | 理解调用中每张请求图片的总像素预算 |
| `requestImageMaxBytes` | `1048576` | 每张请求图片的编码字节目标；质量阶梯中最小的可用输出会被采用 |
| `maxCacheEntries` | `64` | 每条路由缓存的图片描述条数 |

生成的[配置目录](../../../docs/config-catalog.zh.md#deepseek-aidsh-image-understanding)是所有可接受字段及其 JSDoc 的权威来源。

### 提交图片时会发生什么

向支持图片的路由提交图片，行为没有任何变化。向纯文本路由提交图片时，准入阶段会为它生成一次描述，持久化的 `user/message` 事件同时携带图片块和该描述；目标模型随后在原本只能读到省略提示的位置读到这段描述。没有任何具备图片能力模型的部署也不会新增拒绝：图片照常准入，模型读到的仍是省略提示，与今天完全一致。

### 可能出现的问题

已配置但未注册的 provider，或声明的输入模态不含 `image` 的模型，会在第一次理解调用时直接报错而不是降级，因此配置错误会在日志中暴露，而不是让每张图片都静默退化。某张图片调用超时、报错或返回空文本时，只有它自己没有描述，同一批里的其他图片照常成功。其余所有失败都会记入日志并退化为省略提示；任何失败都不会拒绝用户的消息。

## 实现说明

<details>
<summary>实现内部细节 —— 点击展开</summary>

可观察行为已完整记录在[使用本包](#use-this-package)。

### 设计决策

- **在准入时描述，而不是在循环内描述。** 网关准入提示词时就已经掌握权威路由与目录元数据，而请求瀑布要到之后才解析路由；把描述附加在构建持久化 `user/message` 的地方，可以让模型将读到的这段文字只有一个归属者。
- **只描述路由读不了的内容。** 判断依据是目标路由声明的 `inputModalities`，声明缺失表示未知而非纯文本，因此未知路由永远不会被静默降级。
- **只降级，不阻塞。** 只要存在可用路由，其后的一切失败 —— 超时、provider 报错、空补全 —— 都只对受影响的那一幅图片没有描述，消息本身照常准入。
- **指令属于路由标识。** 改动它会改变部署下所有描述的形式，因此它与 provider、model 一起进入缓存键。

### 调用路径

[`src/consumer.ts`](src/consumer.ts) 中的 `describeForRoute` 是准入路径唯一需要的入口：当路由支持图片或未挂载本服务时它返回空描述，否则委托给已挂载的 `ImageUnderstanding`。[`src/index.ts`](src/index.ts) 中的 `LlmImageUnderstanding` 只解析一次路由 —— 用 `resolveModelInfo` 校验显式配置的组合，或扫描 `listModels` 找到第一个声明支持图片输入的模型 —— 然后按条目从有界缓存取用，或在 `deadline` 超时约束下发一次流式调用。它的请求把图片块和指令放在同一条用户消息里，并带上 `purpose: 'image-understanding'`；首个文本块经过裁剪、按码点边界截断后进入缓存。`dsh-llm` 中的 `projectImagesForTextModel` 在持久化块带有描述时渲染描述，否则渲染省略提示。

### 源码地图

| 文件 | 职责 |
|---|---|
| [`src/index.ts`](src/index.ts) | 服务定义 `ImageUnderstanding`、Provider `LlmImageUnderstanding`、路由解析、缓存与有界调用 |
| [`src/consumer.ts`](src/consumer.ts) | 准入侧辅助函数：判断并委托，任何失败都降级 |
| [`src/types.ts`](src/types.ts) | 路由与结果的词汇表 |
| [`src/invariant.ts`](src/invariant.ts) | 不变量伴侣（无运行时不变量；描述通过准入路径追加的 `user/message` 事件进入会话日志） |

<a id="model-experience"></a>
## 模型体验

### 目标路由声明只接受文本输入时的描述调用

#### 模型看到什么

一条用户消息，内容是图片块后跟指令文本。图片块携带持久化归一化后的附件，因此视觉模型看到的是已存储的那张图片本身。

##### 随每张图片发送的指令

```markdown
Describe what this image shows for a reader who cannot see it. Transcribe visible text verbatim, including labels, code, and error messages. Answer in plain prose with no preamble.
```

#### Token 影响

条件性：每次调用一张图片加一条指令，输出受 `maxOutputTokens` 限制。支持图片的路由不产生调用，也不产生 token。

#### KV Cache 影响

独立的模型请求：它与智能体循环不共享任何前缀，因此既不复用也不会使循环的缓存失效。重复且完全相同的调用可以复用描述器自身在 provider 侧的缓存。

### 已准入消息上的描述文本

#### 模型看到什么

对于纯文本路由，目标模型会在原本只能读到省略提示的位置读到描述，位置与图片原来所在的位置一致。其中 `<model>` 是描述模型的 id，`<digest>` 是附件摘要，`<text>` 是生成的描述；支持图片的路由看到的是图片块，没有任何描述文本：

##### 替代图片渲染出的描述

```markdown
[image description generated by <model>; attachment sha256:<digest>: <text>]
```

#### Token 影响

替换式：图片在请求中的 token 被换成有界的文本，长度上限为 `maxDescriptionChars`。

#### KV Cache 影响

描述在其归属事件落盘时即已固定 —— 准入的 `user/message` 或落盘的 `tool/result` —— 因此该持久化事件是纯追加的，并保留其之前的前缀。有界缓存可以在多轮之间为同一个附件复现同一段文本，而不会改变它。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与未竟事项

以下限制说明本包能做什么、不能做什么；它们是本包当前的约束。

- **仅覆盖网关入口与工具结果** —— 描述在能为调用方解析路由的地方附加：Remote 的 `session/prompt` 与 `session/updateQueue` 准入路径，以及 `dsh-agent-loop` 中的 `tool/result` 落盘点。直接构造 `user/message` 块的子智能体、ACP 或其他进程内调用方拿到的仍是省略提示，因为没有准入路径会为它解析路由。
- **一次调用一张图片** —— 同一条消息里的图片各自独立描述，因此一批图片中每张未缓存的图片都要一次调用，无法共享前缀。
- **缓存仅限单进程** —— 已保留的描述只存在于挂载服务生命期内的内存中，重启后会为会话日志仍在引用的附件重新生成描述。

#### 开放问题：直接构造内容块的调用方

子智能体、ACP 或其他不经过网关准入、自行组装 `user/message` 块的进程内调用方，拿到的仍是省略提示，因为没有人为它解析目标路由。要补上这个缺口，需要一处这些调用方与网关共用的落点，而这样的能力缝目前还不存在。
