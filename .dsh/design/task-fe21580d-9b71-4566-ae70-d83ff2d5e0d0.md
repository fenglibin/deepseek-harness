- [revision 3] ## 决策

在 Chat View 投影层，把「模型自身参数写错、用户无从处理」的 edit 失败行标记为 `visibility: 'hidden'`。

判定依据是 `tool/result` 事件上**已持久化**的 `error: { name, code }`（`ToolResultNode.error`），白名单：

- `FS_EDIT_NOT_FOUND` —— 字面量在文件里找不到（或 `old_string` 为空）
- `FS_AMBIGUOUS_EDIT` —— 字面量匹配到多处且未开 `replace_all`

### D1 判定用持久化 error code，不用消息文本

`tool/result` 事件的 `data.error` 由 `ToolResultNode.error` 承载，是核心里 `errorInfo()` 对 `HarnessError` 子类投影出的 `{ name, code }`，随会话日志持久化、可 replay。用 code 判定可测试、可精确路由，且不与消息文案耦合（文案在 `fs-local` 与 `tool-str-replace-editor` 里各写一份，措辞不同）。

`FS_EDIT_NOT_FOUND` 在三处被抛出：`fs-local/src/fsio.ts:768`（空 old_string）、`:773`（找不到）、`fs-e2b/src/index.ts`、`tool-str-replace-editor/src/index.ts`（old_str 未出现）。`FS_AMBIGUOUS_EDIT` 在 `fsio.ts:776` 与 `str_replace_editor` 各一处。它们共用同一对 code，因此一处白名单覆盖全部三类后端。

### D2 新投影与既有条件式投影分开，不做成同一个集合

`RecoveredMutationProjector`（`recovered-mutation.ts`）已经隐藏 `FS_NOT_OBSERVED` / `FS_STALE_VERSION`，但语义不同：它的隐藏是**有条件**的——必须存在一处锚点更晚的同路径成功 mutation。本次要的是**无条件**隐藏（该失败无论后续是否成功都不该出现在页面上）。把这对 code 塞进 `RECOVERABLE_CODES` 是错的：那会让它们在没有后续成功时仍然可见，而点开截图里的场景恰恰是模型失败后不再重试。

因此新增一个独立投影，沿用同一 `replace` / `apply` 形态以保证装配一致性，但不持有任何跨节点状态。

### D3 折叠范围包含 PTC 嵌套子调用行

`edit` 在 PTC 模式下会作为 `run_code` 的嵌套子调用出现，宿主于父行的 `subCalls` 内，而非独立 View 节点。子调用行的 `ToolResultNode` 由 `childResult()` 构造，**不带** `error` 字段（`tool/code-dispatch` 数据里没有 error），所以按 code 判定覆盖不到子行。

保留根因：`childResult` 的 `content` 来自 dispatch 事件的 `content`，而失败子调用的 code 只在模型可见的文本里。为避免解析文本，本次对子调用的处理是：父行可见性照常由 code 决定；子行不单独隐藏（无 code 可判）。**待确认点已与用户对齐为「也隐藏子调用行」，实现时需评估在 `childResult` 侧保留 dispatch 的失败 identity，或由父行整体承载。** 这一点在 tasks 中作为独立步骤验证其可行性，若 `tool/code-dispatch` 事件确实不携带 error identity，则需在 `tool.ts` 的 dispatch 折叠处补上该字段的传递。

### D4 与既有 Agent Note 的决策反转

`2026-09-04-chat-ux-recovered-mutation-errors-hidden.zh.md` 的 Alternatives 明确记载「非临时性失败（无匹配、权限拒绝）是有意义的，必须保持可见」，且 `conversation-node-definitions.client.spec.ts` 有一条断言 `FS_EDIT_NOT_FOUND` 保持可见的用例（"keeps a non-recoverable mutation failure visible even when a later mutation succeeds"）。

本次决策反转该范围（仅针对这两个 edit code，不涉及权限/沙箱类失败）。按 `.agents/notes/AGENTS.md` 的归档规则：这是决策反转，需要**新 Note** 并在其中交叉链接旧的；旧 Note 保持 implemented 不归档，但其 Alternatives 段需就地更新为当前事实，避免留下与现状矛盾的权威表述。

### D5 不触碰模型侧

`tool/result` 的 `content` 与 `error` 一行不改：模型仍收到完整的错误文本与可路由的 code。改动严格限于 Client 的视图投影，符合 packages/client/AGENTS.md 的「web 层是纯呈现」——该行是否显示属于「怎么画」，不进会话日志。

检查 `~/.dsh/sessions/--Users-fenglibin-data-code-opensource-deepseek-harness--/` 下 43 个会话（`session.jsonl.zstd`，`zstd -dc` 解压）：

**结论**：本次只做顶层。子调用覆盖写入 Known Limitations，待 PTC 部署形态真实出现且需要时再评估。

### D7 实现承载点

新增 `HiddenToolFailureProjector`（与 `RecoveredMutationProjector` 并列），在 `chat-snapshot-builder.ts` 的 `replace` / `apply` 链上装配：
