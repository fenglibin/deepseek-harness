- [revision 3] 方案已与用户对齐，完整设计见 docs/plans/2026-09-16-session-file-changes-diff-and-revert-design.md。

核心结论：
1. 现状「修改的文件」由宿主投影 dsh-file-changes（折叠完整会话日志，产出 changedFiles）与客户端 dock ui-session-changes 两层构成。FileChangeEntry 只有 path/operation/firstSeq/lastSeq，不含内容，因此现在产不出 diff。
2. 零侵入捕获点已验证：packages/core/tools/src/index.ts:167 的 tools/post-execute waterfall，其 exec.agent.session 即 Session 对象，ToolExecutionSuccess.value 携带 write/edit 返回的 before/after 全文。因此新增插件无需修改 dsh-tool-fs 任何代码。
3. D1 边界：以 Session 为边界，子代理是独立 Session，按用户选择沿 header.parentSession 聚合本会话及子孙子代理。
4. D2 语义（用户纠正后的关键修正）：累积 diff = 会话启始态 → 会话末态，而非 → 当前磁盘内容；撤销 = 把会话改动从当前磁盘内容里减掉，保留外部/其它会话的改动。每 path 只存第一次的 before 作基线，存最后一次 after 作末态，不存中间态。
5. D3 撤销用 jsdiff v9 反向 patch，逐 hunk 应用、fuzzFactor:1 容错；已实测：agent 改 line2/用户改 line5 → 正确还原且保留用户改动；真冲突返回 false 整体拒绝不半改文件；多 hunk 冲突时逐 hunk 重试可保留局部成功。
6. D4 大文件降级：超 diffBasisMaxBytes 时不预览但仍可撤销（基线完整保存）。
7. D5 「接受」与「撤销」并存，语义不同（接受是 UI dismissal 不动磁盘，撤销是真还原）。
8. D6 实现为三个新包（fs/session-file-revisions 宿主核心、api/session-file-revisions Remote 命名空间、扩展 ui-session-changes dock UI），复用既有 DiffBlock 原语，装配只改 web-app cordis.patch.yml，主工程零改动。

已确认的注意事项：LF 归一化基一致、基线字节上限配置化、并发以 seq 最大者为末态、撤销后清除或推进基线、新建文件（baseline=null）撤销时若非空则保留并报告而非直接删除。
