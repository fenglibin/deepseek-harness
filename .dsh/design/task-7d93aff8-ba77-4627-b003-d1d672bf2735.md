- [revision 2] ## 现状（实测，来自 packages/client/ui-session-changes 与 ui-deliverables）

- dock 条目 `session-changes` 注册在 `conversation.input.dock`（`src/client/index.ts`），组件 `SessionChangesDock.tsx` 用 `useConversation` 读会话快照，`sessionChanges(conversation)` 折叠每个 turn 的 `deliverables` 数据（`{ seq, path, operation }[]`）。
- **已有去重**：`sessionChanges` 用 `Map<string, MutationOperation>`，键是 `produced.path` 原始字符串；`ui-deliverables` 的 `producedForClosing` 也有同路径 `seen` 集合。因此"完全相同的路径字符串"不可能重复出现。
- 重复的真实来源（两条）：(a) 同一文件被写成不同拼写——绝对路径与工作区相对路径（`write`/`edit` 的 `file_path` 由模型给出，`str_replace_editor` 另用 `path`）；(b) 不同目录下的同名文件，因行内只显示 `workspaceTitleOf(path)`（basename）而看起来重复。
- 行内目前渲染 `<span className={css.path} title={change.path}>{workspaceTitleOf(change.path)}</span>`：既不可点，也看不到路径。
- 打开能力现成：`ctx.remote.session.openWorkspacePath({ path })` + `resolveWorkspacePath(cwd, path)`；ui-chat 在 `conversation.view` 的 inject 里实现了 `openFile`（`apply.ts:120`），会话页的 ProducedFiles 芯片靠它打开。dock 的 owner 是 `InputZone { session, input }`，不带打开能力；`InputActions` 也没有 notify。

## 决策

1. **规范化路径后再去重**：新增纯函数 `canonicalMutationPath(path, cwd?)`——先用 `resolveWorkspacePath(cwd, path)` 把相对路径解析到工作区，再按 `/`、`\` 切分，丢弃空段与 `.`，遇 `..` 回退一段。折叠键与展示文本都换成规范化结果，于是 `src/a.ts` 与 `/proj/src/a.ts` 收敛成一条。
2. **cwd 从 inject 取**：session 作用域的 register 的 inject 工厂收到 `sessionId`，用 `ctx.sessions.list.getSnapshot().byId[sessionId]?.cwd` 读工作区根（与 ui-chat 同源）。注入面 `SessionChangesInjected { cwd, openFile }`。
3. **openFile 只做一次转接**：因为 `change.path` 已是规范化（已解析 cwd）的绝对路径，dock 的 `openFile` 退化为 `ctx.remote.session.openWorkspacePath({ path })` 的一行转接，不复制 ui-chat 的 cwd 解析与抛错文案逻辑。
4. **全文名 + 可点**：行内改为 `<button>`，内容拆成目录段（可压缩省略）与文件名段（永不省略），`title` 与 `aria-label` 承载完整路径；`t('open', { name })` 作为无障碍名。
5. **失败呈现就地**：面板持有 `openError: string | null`，`openFile` 被拒时把宿主消息渲染到列表下方一行（`role="alert"`），下次成功打开时清除；不引入 toast/弹窗机制。
6. **文案归字典**：新增 `open`、`openFailed` 两个 key，经 `t` 出组件。
