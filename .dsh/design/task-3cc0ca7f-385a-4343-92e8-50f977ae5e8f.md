- [revision 2] ## 根因诊断（需求 5）

`packages/mcp/mcp-manager/README.zh.md` 已记载：mcp.json 到 settings 的同步是单向且整节的，结构化表单的写入会在下一次 mcp.json 变化时被覆盖。当前「编辑」表单走 `McpStore.update → scope.mutate` 写 settings.yml 的 `mcp` 命名空间，而 mcp.json 只经 chokidar 单向同步回 settings、从不反向写回。因此编辑 settings.yml 后 mcp.json 仍是旧内容，下一次 mcp.json 变化即整体覆盖还原，表现为「编辑不生效」。

## 修复方案

让「编辑」与「配置MCP」都直接读写 mcp.json，写入后主动、同步触发 syncMcpJson()（经 scope.replace → watch → apply → reconcile 立即重连），不再依赖 chokidar 的 awaitWriteFinish 延迟。

## 接口设计（Host mcp-manager 新增 @Remote 方法）

1. readMcpDocument(signal) → { text: string }：读 mcp.json 全文，缺失时 bootstrap。
2. writeMcpDocument(text, signal)：parseMcpJson + mcpJsonToSettings 全量校验（JSON 语法 + mcpServers 结构 + 每条目 command/url），失败抛 RemoteError 附具体信息；通过后 writeFile 并立即 await syncMcpJson()。
3. updateMcpServer(entry: McpServerEntry, signal)：读 mcp.json → settingsToMcpJson({servers:[entry]}) 转单条 McpJsonServer → 替换/插入该 serverName 条目 → renderMcpJson 写回 → 立即 await syncMcpJson()。

syncMcpJson 幂等：写入后 watcher 二次触发读到相同内容，commit 里 deepEqualJson 相等不重复 apply。
