- [revision 3] 完整设计见 docs/plans/2026-09-16-workspace-file-browser-design.md。

可行性：语法高亮、树形浏览、Host↔Client 通道、大文件字节路由、浮层挂载点均有现成能力，无需新造轮子。

两个硬约束决定架构：
- packages/fs/fs/src/index.ts 的 FileSystem 抽象类没有 mkdir/remove/rename，因此新建/重命名/删除不能落在 ctx.fs 上；扩展该 seam 要改抽象类型 + fs-local + fs-sandbox 两个后端，影响面最大。按用户确认，新插件包自带窄 Host IO 实现（node:fs/promises + 同目录临时文件 rename 原子发布）。
- packages/client/ui-workspace/src/client/rows/Rows.tsx:129 的 workspaceMenuItems 是硬编码的 rename/delete，无扩展点，这是唯一必须改动的既有功能文件。

决策摘要：
D1 新增 ctx.workspaceRowMenu 注册表服务（由 ui-workspace 拥有并提供），贡献项只承载 JSON 兼容数据 + onSelect 回调，不含 icon（ReactNode 禁止跨 UI 域）。
D2 Host 落点是单个自包含包 packages/api/file-browser（Remote namespace fileBrowser）；不拆 IO 服务 + Remote 包装两个包，因为 IO 只有这一个消费者。
D3 安全边界：每次调用用 ctx.workspaceRegistry.get() 解析工作区根，目标 realpath 后做包含检查（同 fs-sandbox/src/containment.ts 模式），越界抛 file-browser/outside-workspace。
D4 read 返回四臂判别联合 text/image/binary/too-large，承载「仅文本可编辑、图片可查看」；上限默认 2 MiB；语言判定放 Client（表现层事实，highlight.ts 的别名表本就是 client 侧唯一权威）。
D5 写入用 mtimeMs+size 摘要作 version 做乐观锁，不匹配抛 stale；同目录临时文件 + rename 原子发布。
D6 图片字节走精确 Fetch 路由 /api/file.asset（connection.fetch.register，同 session-log-export），浏览器 img 直连；不走 Remote base64。
D7 Client 落点 packages/client/ui-file-browser；apply 内两次注册（菜单项 + shell.overlay Modal）共享闭包内创建的可观察打开请求源，不引入 store 或模块级单例。
D8 编辑器为 shiki 高亮层 + textarea 叠加（用户确认不引入 CodeMirror/Monaco）。
D9 树懒加载、默认隐藏 dotfile 与 node_modules/.git/dist 等重目录、文件名搜索由 Host 递归并有上限。
D10 默认进入 web-app 组合。

模型可见性：本功能不注册提示词、工具或会话事件，模型完全不可见。
