- [revision 2] ## 问题（实测证据，来自 ~/.dsh/sessions 与现网调用）

1. 会话标题能力已存在且被触发：每个会话都落盘了 `session/title-llm-request`，但 12 个近期会话的 `session/title` 全部是 `source.kind: "fallback"`，即界面上看到的"用户首问前几个字符"。
2. 根因是辅助请求的 `maxTokens: 64` 被思考 token 吃光：默认路由 `tencent-tokenplan / hy4-preview` 返回 `finish_reason: length`、`completion_tokens_details.reasoning_tokens: 64`、`content: ''`，`finishError()` 把 `max-tokens` 判为失败 → 回退兜底标题。
3. 该端点忽略一切关闭思考的参数（实测 `enable_thinking`、`reasoning_effort: minimal`、`thinking.type=disabled`、`thinking.enabled=false`、`chat_template_kwargs`、`extra_body` 全部无效）；预算加到 128/256/512/1024/2048/4096 仍只出思考不出正文（hy4 在该提示词上原地兜圈）。任何"调大预算"的方案对 hy4 都不成立。
4. 同账号的 `tencent-tokenhub-llm / glm-5.3-flash` 用同一套提示词在 6.8s、228 个思考 token 内产出 `优化会话标题生成：调用LLM总结用户提问`（正好 20 字）。所以"给轻量任务配一个能干活的模型"才是真解，且 64 token 对任何思考型路由都太小（glm 实测需 228）。

## 设计

### 1. 新包 `packages/core/lightweight-model`（`@deepseek-ai/dsh-lightweight-model`）

照 `packages/core/agent-default-model` 的最小范例：

- Service `LightweightModelConfig`，`ctx.lightweightModel`。
- settings 命名空间 `lightweight-model`，schema `{ provider: string; model: string }`，两者同时为空 = 不启用（默认）。
- API：`currentSelection(): LightweightModelSelection | undefined`（未启用返回 undefined）、`saveSelection(next)`、`clearSelection()`。
- 通过 `settings.installSection()` 挂载，deployment 层可通过 cordis.yml 给 base 值。

### 2. 消费方：所有 `purpose` 标记的辅助调用

`GenerateOptions.purpose` 只有 `'compaction' | 'session-title'` 两个成员，正好是仓库自己对"轻量辅助调用"的定义。统一解析顺序：

- `packages/session/session-title-llm/src/index.ts` 的 `resolveRoute()`：显式 `provider`+`model` 配置 > **轻量模型** > 继承 `request/header` 主路由（缺失时仍报同样错误）。
- `packages/compaction/compaction-basic/src/summarizer.ts` 的 `summarizeWithLlm()`：`summarizationProvider/Model` 覆盖 > **轻量模型** > 最新主请求路由 > Agent options（缺失时保留原错误消息语义）。

用 `ctx.get('lightweightModel')` 读取（服务可选，未挂载时降级，不破坏无 settings 的部署）。

### 3. base bundle 标题策略

`packages/bundle/base/cordis.patch.yml` 的 `session-title-llm` 行：`targetCjkCharacters: 10 → 20`，`maxOutputTokens: 64 → 512`（覆盖 glm 实测的 228 思考 token 并留余量），`timeoutMs` 保持 60000。

### 4. 客户端：设置 → 模型 页的「轻量模型」卡片

在 `packages/client/ui-settings-models` 新增一张卡片：从 `ctx.remote.session.modelCatalog()` 的已配置模型中单选一个作为轻量模型，可清空（清空 = 跟随主对话路由）。照 `packages/client/ui-settings-plugins/src/client/subagent-model-selection-card-controller.ts` 的既有模式（catalog 加载 + settings scope 修订号围栏写入 + 暂存/保存/丢弃）。文案走 locales.ts 中英成对。

### 5. 文档与记录

- `docs/design/lightweight-model-routing.md`（中英）记录本次决策与 hy4 实测数据，填补"轻量任务是否用独立轻量模型"此前无记录的空白（已搜索 `docs/design/`、`.agents/notes/` 含 archived，确认无历史记录）。
- 双语 README、config-catalog 重新生成、会话标题子系统的"已知限制"补充"思考型路由会把思考 token 计入 `maxOutputTokens`"。
- Agent Note（非平凡改动，仓库约定）。

## 不采纳的方案

- **只调大 `maxOutputTokens`**：hy4 在 4096 仍不出正文，对默认路由无效。
- **在仓库 base bundle 里硬编码用户的私有 provider**：那是用户级 `~/.dsh/profiles/web/cordis.patch.yml` 的职责。
- **新增"关闭思考"的通用开关**：实测目标端点不支持，属于幻觉式可配置性。
