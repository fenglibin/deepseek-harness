- [revision 4] 设计登记：完整设计文档在 `openspec/changes/add-deferred-native-dependency-loading/design.md`（D1–D6）。摘要如下。

**D1 加载失败必须发生在错误重包装之前。** `probeImage`/`detectImage`/`normalizeImage` 三个入口各自都有 `catch` 把非 `AttachmentError` 重包装为 `AttachmentError`（`INVALID_IMAGE` / `ATTACHMENT_WRITE_FAILED`）。改造后加载失败发生在函数体内，若把 `requireSharp()` 放进 `try`，缺失的原生绑定会被报成"图片数据无效"，把环境故障伪装成数据故障。因此三处调用点都落在 `try` 之外；`normalization.ts` 的 `preparedPipeline()` 新增首个参数 `sharp: ReturnType<typeof requireSharp>`，取值放在 `canPassThroughNormalization()` 早返回之后（直通路径不需要原生栅格能力），调用点同样在 `try` 之外。

**D2 `encoding.ts` 不动。** 它已是 `import type { Sharp }`，type-only 导入不进入运行时模块图。`normalization.ts` 与 `image.ts` 保留 type-only 的 `Sharp` 用于签名标注，只移除值导入。

**D3 `sharp` 留在 `dependencies`。** 延迟加载改变加载时机，不改变依赖必要性；缺了 `sharp` 图片附件功能整体不可用。标成 optional 会让安装静默成功、故障推迟到运行时，与「错误配置要大声失败」相反。

**D4 适用范围按本地包清单逐项判定。** 适用：`attachment-local`（三处 sharp 值导入，且被 `cordis.patch.yml` 默认挂载）、`win32-process`、`sandbox-windows-acl`、`subprocess-local`（node-pty + koffi）、`terminal-bash`。不适用：`api/terminal-controller`（本地无此包）、`subprocess-local/src/linux-execve.ts`（本地无此文件）、`benchmarks/`、英文 README 与 `*.i18n.yaml`（本地中文单语 fork）。

**D5 本地既有启动期堆水位机制保持原样。** `packages/api/session-controller/src/heap-watch.ts`、三个 `heapWatch*` 配置项与 `run.sh` 的堆上限/近限快照注释一字不动——本变更只推迟原生模块加载，与堆水位无关。

**D6 同时移植 `terminal-bash` 的启动失败清理。** 抽出 `rejectAfterStartupCleanup()`：`createSession()` 抛错时先 `terminal.terminate()` 回收那条已创建但无所有者持有的 PTY，`startupSession()` 失败路径复用它，保留 `TerminalBackendCleanupError` 聚合语义。

**Koffi 的类型注册必须惰性化而不只是绑定惰性化**（D4 的落地要点）：`win32-process` 与 `sandbox-windows-acl` 原先在模块作用域调用 `koffi.pointer()`/`koffi.struct()`，而 Koffi 的类型注册表是进程级全局的，模块作用域注册会让重复求值该模块的测试运行器或语料清扫在第二次注册同名类型时失败。类型与绑定一起收进带缓存的 `win32Types()` / `ffiTypes()`。

**被拒绝的方案**：把 `sharp` 移入 `optionalDependencies`（与 D3 冲突）；把 `requireSharp()` 放进既有 `try`（与 D1 冲突）；覆盖本地 heap-watch 与 run.sh 的堆策略（与 D5 冲突，官方无对应机制）；以 benchmark 数字论证收益（本地无 benchmark 基础设施，收益由加载顺序事实论证）；不实测就跟删 koffi 语料豁免条目（该检查扫构建产物，判定必须发生在产物重建之后）。
