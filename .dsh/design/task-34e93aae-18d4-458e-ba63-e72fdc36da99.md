## 决策
### D1 修掉游离 `)`
直接删除 `DeliveryCard.tsx:185` 的 `)`，并加一条渲染断言测试（卡片容器不含裸 `)` 文本节点），避免复发。

### D2 帮助入口并入描述行
头部整体是 `<button>`（展开/收起），帮助链接也是按钮，嵌套按钮是无效 HTML 且破坏可达性。因此改为：**展开后 body 首行**渲染「描述文案 + 帮助链接」同行，链接紧随描述文本；头部仍保留原描述。移除 `.helpRow` 的 `justify-content: flex-end` 独占行样式，改为行内 flex 基线对齐。

### D3 两列栅格
在 `fields.module.css` 新增 `.grid { display: grid; grid-template-columns: repeat(2, minmax(0, 1fr)); }`，卡片内容包一层。短控件（enum/boolean/number）各自占一列；长控件（list/tag）加 `grid-column: 1 / -1` 整行。窄视口用 `@media (max-width: 720px)` 回落单列。分隔线由 `.field + .field` 改为按行分组（两列时用 `border` 逐格，避免出现半行空线）。

### D4 信号词表改标签式编辑器
新增 `TagField` 控件（`fields.tsx`）：每个值渲染为一个可删除标签（带删除按钮），末尾一个输入框 + 添加按钮/回车添加；空输入不添加、重复值拒绝并提示。`card-form.ts` 新增 `tagField(field)` spec（`control: 'tag'`），值与现有 `listField` 同形（`string[]`），因此 Host schema 不变。三个信号字段与验收命令字段改用该控件。
同时补 locale 文案说明匹配规则：忽略大小写、子串包含、每条命中计 1 次、编号列表额外计 1 个中等信号、可填任意中英文字符串、点添加即新增一条；并在中等信号帮助里点名 `replac` 是刻意词干（覆盖 replace 系列）及其重复计数风险（与 `replace` 并存会算 2 次），同时在词表中**移除 `replac`** 这种不可读词干，改用可读的完整词条集合，消除重复计数与可读性问题。

### D5 验收前置命令改为勾选提示词命令（硬门禁）
- Host `Config`：移除 `postHooks`，新增 `verificationCommands?: string[]`（提示词命令名列表，无前导斜杠）。
- Host 读取提示词命令：经 `ctx.settings` 读 `prompt-commands` 命名空间的 `commands`（节 `name` → `prompt`）。未挂载 settings 或未配置时该字段无候选。
- L2 结构校验保留：`openspec validate <changeId> --strict --json` 仍由 Host 经 `ctx.shell.run` 执行，判定方式不变，**不受本次改动影响**。
- 硬门禁：推进到 `verified` 时，若勾选了验收命令，且当前任务尚未留下「验收记录」，则阻止推进，并把每条选中命令的提示词与「执行后必须调用 record_change 留下验收结果」写进门禁消息（因为 `deferContext` 在抛错路径被丢弃）。模型执行并 `record_change` 后放行。验收记录用带固定前缀的变更记录承载，可机械检查。
- 移除旧 `postHooks` 的 shell 执行路径与其校验；同步更新既有测试。

### D6 Client 勾选交互
交付卡片新增「验收命令」控件：经 `ctx.settingsScope.bind({ namespace: 'prompt-commands' })` 读取命令清单，渲染为复选框列表（复用 SubagentModelSelectionCard 的分组/禁用态样式思路）；命令清单为空时提示先到「提示词命令」页添加。勾选结果写入 `delivery` 命名空间的 `verificationCommands` 字段。

### D7 门禁与契约不变式
ADR 要求「门禁在做出决定的那个操作里执行」。因此硬门禁的判定落在 `advance_delivery_task` 的 `verified` 分支内，而非依赖界面或提示词。
