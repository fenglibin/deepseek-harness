## 设计

### D1 部署侧用 id 覆写而非改 `auto` 语义

`~/.dsh/profiles/web/cordis.patch.yml` 增加 `- id: response-language` + `config: { language: zh }`。profile 是 `patchReload: live`，改完即生效。

否决「让 `auto` 在无法指导的语言上继续往后看」：`packages/context/response-language/README.zh.md` 把「第一个能指名语言的信号终止搜索」写成了契约，改它要同步 README 与 4 条 spec，并会让用户显式选英文的意图失效。

否决「恢复 `LanguageRow`」：与 `docs/design/chinese-only-localization.zh.md` 的纯中文 UI 目标直接冲突。

### D2 思考条款写进同一段落，不新增配置面

`DIRECTIVES.zh` 在散文条款与注释条款之间插入：

> 你的思考过程也用中文，包括推理、计划、自检与取舍说明，不要先用英文推理再转述成中文。

条款点名四类思考内容并显式禁止「先用英文推理再转述」——这是指令只约束正文时最常见的退化形式。位置选在散文条款之后，让「读到的 / 想到的 / 写进代码的」三类对象相邻。

否决 `Config.reasoningLanguage`：部署方没有让思考与正文使用不同语言的真实需求，无消费者证据的配置面只会带来 config-catalog、README 与 Model Experience 门禁的同步负担。

否决单列段落：两段由同一解析结果驱动，拆开只让 `SECTION_ORDERS`、测试与 README 多一个维度。

### D3 既有否决属部分取代，保留旧 note 并双向交叉链接

两条旧 note 的否决理由是「可靠性」而非「方向」；本次改动接受可靠性有限这一前提，只改变英文推理出现的比例，与注释条款本身所处的概率性状态相同。按 `.agents/notes/README.zh.md`，部分取代保留两个记录并互相链接，不合并、不删除。
