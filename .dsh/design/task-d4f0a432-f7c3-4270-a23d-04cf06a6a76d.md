- [revision 2] ## 设计要点

### D1 会话插件开关复用全局开关的交互，但落点不同
全局条目经 `pluginInventory/setEnabled` 写 Loader 条目自身的 `disabled`；会话插件行经 `agentPresets/setRowDisabled` 写它所属预设的 `agent.cordis.yml`。两者在 UI 上是同一个 `StateToggle`：写入后重新读取整份快照，写入被拒时卡片保持展开并报告失败。

放开当前的 `trust === 'user'` 限制：随部署自带的 `system` 预设也接受这一行的写入，写的是 `resolve()` 解析出的组合文件本身。删除预设仍然只对用户预设开放——删除是破坏性的，改一行不是。

### D2 组合文件写入改为保注释的局部编辑
现有实现把整个文件用 `js-yaml` 重新 `dump`，会抹掉文件里的全部注释与手写格式。随部署自带的 `standard/agent.cordis.yml` 有一百多行设计注释，一次开关就会在工作区里永久删掉它们。改为按行定位目标行块：只在 `<keyIndent>disabled: true` 这一行上做增删，其余字节原样保留。行块通过「扫描 `- ` 列表项 → 用 js-yaml 解析该块确认 `id`」定位，因此嵌套在 `group.config` 里的行与 `id` 不是首个键的行都能命中；流样式（`- {id: x}`）插入新行会产生非法 YAML，这类行明确拒绝而不是猜测。

### D3 开关配色改用语义色，不再用 brand
`--dsw-alias-brand-primary` 在浅色外观下是 `neutral-bluish-1000`（近黑）、深色外观下是 `neutral-bluish-50`（近白），作为开关的启用底色在浅色外观下就是一块黑色。改用 `--dsw-alias-state-success-primary`（失败色已在用，成功色语义上就是「开」），它在两套外观里都由主题定义，随外观切换自动变化。

### D4 README 查看器复用 ui-primitives 的 MarkdownText，不新写渲染器
`packages/client/ui-primitives/src/markdown/` 已经是一套完整的 mdast → React 渲染器（GFM 表格、脚注、KaTeX、Shiki 代码高亮、增量流式解析），会话消息就在用它。查看器复用它，只补两处能力：

- **mermaid**：新增可选渲染分支，仅当渲染上下文开启且代码块语言为 `mermaid` 时，改为动态 `import('mermaid')` 后渲染 SVG。动态 import 保证不出现 mermaid 围栏时不加载这几百 KB。
- **整篇文档**：`MarkdownText` 是按消息设计的（流式、脚注区），查看器用同一渲染管线的 settled 分支渲染全文。

### D5 README 内容按需取，不进清单快照
清单快照仍然只带 frontmatter 里的 `description`；另外给每行补一个 `readme` 字段，值是可读到的 README 文件名（`README.zh.md` 优先），它既是「是否显示查看更多信息」的依据，也让客户端不必先猜。全文由新的 `pluginInventory/readme(moduleName)` Remote 在点击时惰性取回——几十个插件的全文不能进每次 list 的载荷。

### D6 查看器形态
模态弹窗（`ui-primitives` 的 `Modal`），居中、可滚动、Esc/遮罩关闭，标题是插件模块短名称 + README 文件名。加载中、该插件没有 README、读取失败各有独立文案。
