- [revision 2] P1 只交付主机端，完整设计见 docs/design/image-understanding-and-inline-images.md（已落盘并通过配对门禁）。客户端内联输入是 P2，不在本任务范围内。

决策 A：新增能力 seam `ctx.imageUnderstanding`，包位于 packages/llm/image-understanding，三角色齐备——Service Definition 声明描述形态与「无描述」这一合法返回值；Service Provider 用一条配置好的视觉路由经 ctx.llm 生成描述；Consumer 在 agent/pre-step 判定哪些图片需要描述。包紧邻它所消费的 llm 能力，作为普通 Cordis 配置项挂载。

决策 B：描述发生在 `agent/pre-step`，不在网关、也不在请求出口。网关只管准入，描述到请求的关联仍要在后面发生；请求出口的 llm/stream 交付给监听方的是深度冻结、未落盘的内容，按仓库约定只能读不能改写。而 agent/pre-step 的 decision 消息随后会被 loop 通过 session.append('user/message') 写进会话日志，同一套机制既产出描述又完成落盘。compaction-basic 借该事件改写消息、plan-mode 借它追加持久状态，模式已确立。

决策 C：描述挂在 `ImageBlock.description` 可选字段上（text + 产出路由身份 { provider, model, instruction }），随 user/message 事件落盘；块保留 attachment，因此两个适配器、transcript 渲染与压缩调查都无需改动，请求投影仍是日志的纯函数。放弃独立 `image/described` 事件：那会新增 SessionEventMap 成员（不认识该类型的构建读取时拒绝整份日志），且消息组装时要多一步关联；代价是同一附件在多条消息里各存一份文本，靠会话内缓存把视觉调用压到每附件一次。

决策 D：网关 `prompt()` 保留检查，但仅当路由缺 image 且没有可用描述路由时才抛 session/attachment-invalid；有描述路由则准入。没有视觉路由的部署保留今天的显式失败，不静默降级为占位符。

决策 E（P1 的子集）：投影分支——带描述的图片块渲染为描述文本并注明来源路由，无描述时保持既有 `[image omitted because this model accepts text only; attachment sha256:xxxxxxxx]`。两段文本都是固定的模型可见字符串，由快照覆盖钉住。

非目标（P2/P3）：客户端内联图片节点与有序 parts 提交；工具结果里的图片（不经 inbox，agent/pre-step 看不到，需要为工具结果内容提供投影点）。

验证：服务、投影分支、Consumer 的单元测试；一个 REAL-composition 测试（真实 cordis.yml 启动纯文本路由 + 替换描述器，断言模型可见请求文本）；一条免密钥录制会话快照钉住模型可见文本。
- [revision 4] 设计修订：决策 B 改为「在准入期描述」（durablePromptContent），放弃 agent/pre-step。实现调研发现一个决定性事实——pre-step 跑在 agent/request 瀑布之前，而路由正是被 installModelSelection()（packages/core/agent/src/model-selection.ts）在 agent/request 里写进去的；session-controller 的 selectionFor(agent).current 又是它的私有 map。也就是说 pre-step 监听方拿不到最终路由，只能拿 session.requestHeader()（首轮为 undefined）或 agent.options 去猜——这正好是设计文档第 8 节标为未决的那个不一致，而在准入期它根本不存在：prompt() 里已经算出了 selectionFor(agent).current 并 resolveModelInfo 过。

同时我原先反对准入期的理由（「描述到请求的关联还要在后面发生」）不成立：durablePromptContent()（commands.ts:586）构造的 ContentBlock[] 直接进 createUserMessage() → agent.followup/steer → 作为 user/message 落盘，所以它就是把描述挂到 image 块上的天然 join 点，不需要任何额外关联步骤，也不需要 agent/pre-step。

代价是覆盖范围收窄到经网关的准入路径（GUI 与 API prompt）；subagent 与 ACP 的 ingress 有各自的 content 构造，保持今天的行为，作为同 PR 文档化的后续项。另一处代价是准入 RPC 变慢（描述调用发生在 prompt 请求内），这正是此前确认要加非阻塞提示的那几秒。

其余决策（A/C/D/E 的投影部分）不变：能力 seam 三角色、描述挂 ImageBlock.description 随 user/message 落盘、网关拒绝只在无描述路由时保留、投影按有无描述二选一。
