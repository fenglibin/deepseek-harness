- [revision 3] # 导入技能弹窗：预览与保存拆分

## 现状与问题

`packages/client/ui-settings-skills/src/client/ImportSkillDialog.tsx` 把三件事挤在一个弹窗里：来源表单、内联预览区（文件树 + 只读编辑器）、写入按钮。结果是一个 680px 宽的弹窗里同时塞表单和两个窗格，预览区被压得很窄；而底部按钮还会在「预览」和「写入」之间切换身份，同一个位置先后承担两个不同动作。

## 决策

### D1 预览拆成独立的只读弹窗 `SkillImportPreviewDialog`

新增 `src/client/SkillImportPreviewDialog.tsx`，与 `SkillEditorDialog.tsx` 同构：左侧 `SkillFileTree`，右侧 `SkillFileEditor`，宽度取编辑弹窗的 `min(1100px, 92vw)`。差别只有两点：标题是「预览 {name}」而非「编辑 {name}」，且 `SkillFileEditor` 恒为 `editable={false}`（textarea 走 `readOnly`）——落盘的就是压缩包里的字节，预览里没有任何编辑入口。

导入表单据此缩回它本来的宽度（`importDialog` 的 680px），只留页签、目标根、来源/文件三项。

### D2 预览弹窗叠加在表单之上，关闭后回到表单

表单弹窗保持挂载，预览弹窗是第二个 `Modal`。这样读者关闭预览后来源与目标根都还在，可以改来源重看，或直接点「保存」。

叠加带来一个真实缺陷：`Modal` 用 document 级 keydown 监听处理 Escape，两个弹窗同时打开时一次 Escape 会触发两个 `onClose`，把表单一起关掉。修法在 `ImportSkillDialog` 本地：表单弹窗的 `onClose` 在 `preview !== null` 时直接返回，因为此刻它在栈底。Escape 事件先到表单的处理器（挂载更早，无效），再到预览的处理器（生效）。遮罩点击不受影响——上层遮罩盖住了下层。

### D3 底部固定三个动作：取消 | 预览 | 保存

按钮不再变身份。关闭预览弹窗后保留已解析的 `preview`，所以「保存」可以直接复用，不必重新解析;来源、目标根、页签任一变化仍然清空它（既有规则：批准的清单必须属于它被解析时的来源）。

### D4「保存」直通落库，不展示预览

Host 契约决定了 `commitImport` 只接受 `previewId`，而 id 只能由 `previewImport`/`previewUpload` 解析产生（`packages/host/skill-manager/src/index.ts:355,431`）。所以「保存」= 解析 + 校验 + 写入两步连做，读者看不到中间产物，这正是用户要的「这里就不需要预览了」。

唯一的例外：解析结果显示 `replaces` 为真时，「保存」就地显示 `importReplaces` 文案并保留表单，不发起 commit。Host 已经在预览里给出了结论，再打一次注定被 `skill-admin/entry-exists` 拒绝的调用没有收益，而中文界面下这句本地化文案比 Host 的英文 message 更可读。Host 仍是最终裁决者，它自己的检查一行未动。

### D5 文案与只读性

`importCommit`/`importCommitting`（写入/正在写入…）替换为 `importSave`/`importSaving`（保存/正在保存…）。新增 `importPreviewTitle`（预览 {name}）与 `importPreviewClose`（关闭）。预览弹窗顶部承接原先内联区的元信息行（文件数、总字节、目标路径）与 replaces 警告。
