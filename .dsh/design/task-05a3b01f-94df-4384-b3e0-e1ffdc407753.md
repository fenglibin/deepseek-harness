- [revision 3] ## 设计摘要

完整设计见 `docs/plans/2026-09-18-unactionable-tool-failure-visibility-design.md`；实施清单见 `openspec/changes/update-tool-failure-row-visibility/`。

### D1 反转可见性判定

`packages/client/ui-chat/src/client/conversation-nodes/hidden-tool-failure.ts` 从「黑名单隐藏」（仅 `FS_EDIT_NOT_FOUND`、`FS_AMBIGUOUS_EDIT` 两码）改为「可处置白名单展示」：白名单五码（`FS_SANDBOX_DENIED`、`FS_PERMISSION_DENIED`、`NO_PROVIDER`、`GOAL_TOOL_AUTHORITY_REQUIRED`、`SEARCH_FAILED`）保持可见，其余 `isError` 行默认 `visibility: 'hidden'`，含无 `error.code` 的裸 `Error`。判定按持久化 `error.code`，不解析消息文本。

`RecoveredMutationProjector` 在本变更下被删除：其两个错误码已无条件隐藏，该投影不再改变任何输出。

### D2 拆出精确码

`packages/fs/fs/src/types.ts` 的 `FsErrorCode` 新增 `FS_OFFSET_OUT_OF_RANGE`；`packages/fs/tool-fs/src/read-render.ts` 的越界改抛该码。这是 D1 的必要前提——否则默认隐藏会误吞语义为「文件真的不存在」的 `FS_NOT_FOUND`。

### D3 不引入 turn 终态兜底与阈值汇总

`turn-error`（`conversation-nodes/turn-error.ts:76`）已提供最终失败兜底；提权审批走 `ui-approval` 的 `ApprovalPanel` 独立通道，不依赖错误行。因此纯静默隐藏不会让用户失明，无需额外汇总机制。

### D4 不动持久化格式

`ToolErrorInfo` 的 `{ name, code }` 结构不变；隐藏是纯渲染期决策，不牵动两个 SDK 的期望输出与 `snapshots/` 会话快照。

### 文档与记录合并

新增 Agent Note 记录方向反转，合并两份被完全取代的记录（`2026-09-16-unactionable-edit-failure-rows-hidden.zh.md`、`2026-09-04-chat-ux-recovered-mutation-errors-hidden.zh.md`）；同步 `ui-chat`、`fs`、`tool-fs` 的 README 与 JSDoc。

### 证据基础

本项目 140 个会话、29,038 次 `tool/result` 全量统计：492 次失败中需要用户介入的仅 6 次（1.2%）。`FS_NOT_OBSERVED`(153) 与 `FS_STALE_VERSION`(118) 两类占 55%。`DELIVERY_POST_HOOK_FAILED`(7) 的源码已在 `c78e5ae256` 删除，现存记录为历史 replay——这独立印证了判定必须是白名单制而非黑名单制。
