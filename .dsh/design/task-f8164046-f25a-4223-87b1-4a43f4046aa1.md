- [revision 3] 设计草案落盘于 docs/design/delivery-llm-grading.zh.md（含背景实测表、已确证事实表、D1-D4 决策、备选方案、影响面）。要点：

### D1 删除三张词表，只保留长度闸门

strongSignals/mediumSignals/weakSignals 三个 Config 字段、settings schema 字段、三份 DEFAULT_* 常量、countHits/scanSignals/SignalHits 及客户端标签控件一并删除。唯一保留的机械分级是「目标文本长度 > 200 字符 → L2」。按用户决定同时删除 designThreshold.descriptionChars（原 ≥60 字强制 L1）——它与 200 字闸门同类，留着会让大量普通请求在 LLM 判定前就被升为 L1，使 LLM 判定形同虚设。

### D2 判定由独立辅助 LLM 调用执行

pre-step 在收到直接人类请求且无当前任务时发一次辅助模型调用，把分级规则作为 system 提示词传入，解析返回分级后据此建任务。选它而非注入提示词让主模型自判：后者在模型不遵守时判定就不发生，正是自动触发方案要消除的失效模式。代价与对策：每步阻塞（compaction-basic 已在同一位置 await 模型调用，模式已确立，且只在无任务时才发）；失败必须有确定性回退，超时/失败/不可解析时回退 l1 而非 l0（判定失败应得到纪律而非静默放行）；新开的模型调用按「模型可见 ⟺ 已记录」必须留有会话事件，仿 session/title-llm-request 记录路由、system、messages 与输出上限；路由优先级为 lightweightModel.currentSelection() → 会话最近请求头路由 → agent 自身路由，皆无时回退 l1 而不发调用。

### D3 判定规则是可配置提示词

分级规则不再由代码里的词表承载，而是一段 gradingPrompt 配置文本作 system 提示词，调整识别逻辑不再需要改代码。模型必须只返回一个分级标签；解析取响应文本里第一个出现的 l0/l1/l2（忽略大小写），解析不出即按 D2 回退。默认文本承载原有语义判据（结构契约变更→l2；跨端、跨包、新功能、需设计决策→l1；局部小修→l0），但去掉词表依赖。客户端把三个词表控件换成一个多行文本控件。

### D4 create_delivery_task 保留模型自估值

todo_count/touched_files/is_bug 与 requireOpenspecForBugs 保留：它们不是关键词匹配，而是模型创建任务时自己给出的规模估计，规则求值是确定性的。inferLevel 收缩为「长度闸门 + 这些自估值 + bug 强制」，不再调用 gradeObjective。

关键事实（已逐条读码确证）：countHits 是忽略大小写的子串包含、不支持正则与词边界；gradeObjective 顺序为 >200 字→L2、强≥1→L2、中≥2→L2、中1或弱≥2→L1、否则 L0；compaction-basic 的 pre-step 监听器确实 await 辅助模型调用；session-title-llm 是路由+超时+校验+确定性回退的完整范本且声明了自己的 SessionEventMap 事件；lightweight-model 服务已挂载于 base 组合（cordis.patch.yml:70），无需改组合配置；GenerateOptions.purpose 是封闭联合且 DeepSeek 适配器有消费点（serialize.ts:84、adapter.ts:540/625），若新增取值需两侧同步。
