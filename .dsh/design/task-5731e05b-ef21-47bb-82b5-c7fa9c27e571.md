- [revision 3] ## 现状（已核实）

- 工作区行菜单「文件浏览器」→ `ctx.workspaceRowMenu.register` → `FileBrowserModal`（浏览器形态）。
- 会话页文件链接 → `ctx.fileViewer.open({sessionId,path})` → 同一个 `FileBrowserModal` 的 file 臂（只读）→ 同一个 `contentPane()` → 同一个 `CodeEditor`。
  因此第 4 点的答案是：**两处已经复用同一份内容展示区实现**（`packages/client/ui-file-browser/src/client/CodeEditor.tsx`），改这一处即同时覆盖两个入口，不需要第二套预览实现，也没有另一处需要改。
- 搜索框 = `ui-primitives` 的 `Input`（h32 / font 14px），由 `FileBrowserModal.module.css` 的 `.search` 容器约束宽度（max-width 340px）。
- 「重新加载」「保存」= `ui-primitives` 的 `Button`（size 默认 md：h36 / font 14px）；旁边「已保存」是 12px。

## 决策

### D1 尺寸调整放在 ui-file-browser，不改 ui-primitives 的原子

`Input` / `Button` 是全仓共享原子的默认几何，改它们会外溢到所有消费者。搜索框用 `.search` 作用域内的 CSS 覆盖（28px 高、13px 字号，与树行/标题同级），按钮直接改用已有的 `size="sm"`（28px / 12px），恰好等于「已保存」的字号。

### D2 预览能力落在 CodeEditor，不新增第二个内容区

预览复选框属于内容区工具栏（路径、保存状态、重新加载、保存同处一行），而该工具栏归 `CodeEditor` 所有。把预览放进去，浏览器形态与只读形态同时获得它，符合 D-现状的复用结论。

### D3 预览是「切换」而非「分栏」

勾选后内容区由编辑器切换为预览，取消勾选回到编辑器并**保留未保存缓冲区**。预览渲染的是当前缓冲区（而非磁盘内容），因此未保存的修改也能看到效果；这也让「预览时不能编辑」与「取消勾选后修改仍在」两条同时成立。

### D4 预览类型由扩展名决定，是呈现事实

新增 `previewKindOfPath(path): 'markdown' | 'html' | undefined`，与 `languageOfPath` 并列（前者决定怎么呈现，后者决定怎么着色），都在 Client，因为 Host 只回答字节。

- `.md` / `.markdown` → markdown
- `.html` / `.htm` → html
- 其余 → 无预览能力，不渲染复选框

### D5 Markdown 复用既有 MarkdownText 管线，不新建解析器

`ui-primitives` 的 `MarkdownText` 已是本仓唯一 Markdown 渲染器（GFM 表格/任务列表/删除线、KaTeX 数学、mermaid 流程图、脚注），README 对话框与轨迹视图都用它。开启 `diagrams` 即得到流程图渲染。自建解析器会与它漂移。

### D6 HTML 在 `sandbox="allow-scripts"` 的 iframe 中渲染

`srcDoc={buffer}` + `sandbox="allow-scripts"`：不给 `allow-same-origin`，文档落在不透明源，脚本可运行而 `localStorage`、Cookie 与同源 `/api` 请求不可达。这是与产出 HTML 的实际形态（靠脚本渲染的静态页）相符的最小授权。

**不采用**完全禁脚本：本仓已有实测记录（[从 web UI 打开产出的文件](../../.agents/notes/implemented/feature/2026-07-31-web-workspace-file-links.zh.md)）——报告者工作区四份产物有两份在 CSP sandbox 下是死页面，而且渲染得完美无缺，破坏不可见。

**不采用**同源提供（`iframe src` 指向 Host 路由）：那正是该 note 中实测导致 `/api` 数据泄露的路径，且需要新的 Host 路由与生命周期。

### D7 预览不引入 Host 依赖

`srcDoc` 由客户端已在内存中的缓冲区提供，无新 Remote、无新路由、不改会话日志、模型不可见。
