- [revision 3] 完整设计见 docs/plans/2026-09-13-session-changed-files-accept-state-design.md。

根因：接受集是组件本地 state（SessionChangesDock.tsx:298），按 packages/client/AGENTS.md 与 scoped-slots.tsx 的既有规则，组件本地状态在作用域切换时按构造清空。因此任何重挂载（刷新、切会话往返）都会清空全部接受记录，导致"全部变更的文件又出现"。用户已确认触发场景为刷新与切会话。

语义（经用户确认，含用户对"交集"的纠正）：当前变更 = A[p] 缺失 ‖ lastSeq > A[p]；历史变更 = A[p] 存在（曾被接受过，允许与当前重叠）；全部变更 = 投影全量 F。当前 ∪ 历史 = F 恒成立。file1.ts 接受后再变更时两侧同时存在，再次接受后只剩历史侧且去重为 1 条。

D1 单一真相源 + 接受记录 + 派生视图，不建两份物理列表：历史在数据上等于 Object.keys(A)，"接受时移到历史"由谓词变化自动成立，无需搬移操作，因此不存在漏在两边或历史重复两条的不一致。去重由 A 的 map 键与宿主 fold.ts 的 canonical path 双重保证。可观察行为与双物理列表完全相同。按用户确认只记路径，不冻结接受时刻快照（冻结需另存条目，无法从 F + A 推出）。

D2 接受集提升为 session 作用域 store 并持久化：conversation.input.dock 已声明 scope: 'session'（contract/slots.ts:115），注册时声明 store 后框架按会话缓存实例（registry.ts resolveStore），会话消亡时 clearPersisted 清键（clearStoreScope）。defineStore 的 persist 自动加会话后缀（store/src/index.ts:222）。

D3 保留 pendingChanges 谓词不改（SessionChangesDock.tsx:166 语义已正确），新增 historyChanges 读取 A 的键集合与 allChanges 全量视图。

D4 面板不再在 pending.length === 0 时整块 return null（:207）——否则全部接受后"查看全部"入口也消失；改为收起为一行摘要，仅在从未有变更时不渲染。

D5 已知限制边界：seq 回退（日志修复/回滚后同路径新变更若 seq 不大于已接受值会被判为已接受）；持久化键是绝对路径（工作区移动后旧标记失效）；接受记录随被接受过的路径数有界增长。
