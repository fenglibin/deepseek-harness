- [revision 3] 设计草案落盘于 docs/design/session-revision-persistence.zh.md（含背景、已确证事实表、D1-D7 决策、影响面、风险）。要点：

D1 文案归因：RevisionDiffPanel 用新键 diffFailed（「查看变更失败：{message}」）替换误用的 revertFailed；该面板从不执行撤销。revertFailed 留给 SessionChangesDock.tsx:459 的撤销路径。

D2 错误码分派：客户端不再把 result.error.message 直接当文案，保留 RemoteFailure 上的 code 按码选文案（unknown-path → 「本会话没有记录该文件的改动，无法显示变更」；no-workspace → 「无法确定该会话的工作区」；其它兜底保留原始诊断）。仓库已有保留码的先例（client/ui-settings-skills/src/client/index.ts:47）。

D3 根因修复：新增 storage domain（name: session_file_revisions，layout: per-record，表 sessions 以 SessionId 为键）把每个会话的修订记录持久化。API 为 storageDomain.open(spec) → domain.table(name) → KvTable（packages/storage/storage-domain/src/domain.ts:42-90）；storage-domain 与 storage-json 已在 base bundle（cordis.patch.yml:194-200），web profile 继承，domain 由 storage-domain 自动路由、无需逐 domain 挂载。记录绑定 createdAt/cwd 身份字段，与当前会话头不符即丢弃（理由同 session_projcache，见 packages/session/session-projection-cache/src/spec.ts:33-41）。写入点在捕获后写回，写盘失败不阻断工具执行。容量设 maxRowBytes 上限，超限不写并记日志，绝不截断（截断的基线会让撤销写错内容）。

D4 按行能力判定：客户端改读宿主已有但当前无消费者的 list 动词，用其 entries 决定每行是否提供「查看变更」「撤销」，列表不再出现点开必然报错的行。list 只返回摘要不含全文。

D5 str_replace_editor 携带结构化改动事实：output schema 由纯字符串改为对象并用 oneOf 区分改动类（create/str_replace/insert 携带 path/before/after/operation）与只读类（view 不携带）。render 保持返回逐字相同的文本，模型可见输出与既有测试断言不变。三个 mutator 已持有两侧内容：replaceInFile 读 before（:298）、insertInFile 读 before（:353），FsWriteOutcome 同时给出 before/after（packages/fs/fs/src/types.ts:128-144）。捕获侧据此把它纳入 MUTATION_TOOLS；file-changes/src/mutation.ts:34 本就把它算作变更，这一步让列表与可操作性重新对齐。oneOf 要求至少两个分支（packages/core/tools/src/json-schema.ts:290-296），此处正好两类。

D6 撤销后清理记录：revert 当前从不调用 forget（packages/api/session-file-revisions/src/index.ts:143-153）。内存态下只是让已撤销的行留在列表；持久化后同一条记录会跨重启存活。调整为：status 为 reverted 的路径删除记录，conflict/missing/unchanged 保留。

D7 验证策略：单元覆盖 domain 往返、身份不符丢弃、超限不写、按状态清理；真实装配沿用 capture-e2e.spec.ts 形态补 str_replace_editor 捕获与重启后可读；客户端补 diffFailed 断言、按行能力、错误码分派；快照面已确证工具快照只记 name/description/parameters 不含 output，但 PTC 的 sdkSchemas 会把 output 投影进 SDK 文本（packages/core/tools/src/index.ts:881、:1230），属 public API 变更，需在同一变更内更新 ptc.spec.ts 期望。

关键事实（已逐条读码确证，非推断）：修订记录无法从会话日志重放——tool/result 只保存渲染文本与可选 meta（packages/core/agent-loop/src/tool-calls.ts:313），日志里的 write 结果不含 before/after 全文，故必须自持久化，这也是 D3 选择侧车存储而非重放的原因。
