- [revision 3] 设计草案写入 docs/design/mcp-oauth.zh.md。核心结论：不引入外部插件，复用仓库已有的四个接缝——(1) dsh-credentials 的 GrantRecord（全仓零消费者，正是为授权许可预留的空位，modifyRecord 提供跨进程排他的读-改-写，天然适合 refresh_token 轮换）；(2) dsh-host-webserver 的 WebRoute 承接 OAuth 回调；(3) 既有 McpStatusSink 通道上报 needs-auth；(4) mcp-json 的纯函数往返维持跨厂商兼容。五项决策：D1 auth 判别联合只加在 HTTP 条目（stdio 无端点）；D2 令牌存 GrantRecord 而非 settings 文档（绕开 env/headers 因 wire 整体编辑而丢失脱敏字段的既有陷阱）；D3 needs-auth 是与 failed 并列的独立状态，判别点是"用户动作能否修复"而非"连接是否成功"；D4 无 webserver 时惰性降级，已有 grant 照常使用，沿用 mcpJsonPath 返回 undefined 的同类形状；D5 浏览器半身不实现 OAuth、不持令牌，只新增按钮与徽章，既有 McpStatusStore 经 mcp/status 自动重拉。已拒绝自建令牌文件（外部插件做法，明文落盘且绕开凭据 seam）与在浏览器半身实现 OAuth（违反 web 层纯呈现约束）。
