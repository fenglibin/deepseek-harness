- [revision 3] 设计草案落盘于 docs/design/revision-side-by-side-diff.zh.md，含目标与非目标、现状问题、已确证技术前提表、D1-D8 决策、影响面与风险。要点：

D1 触发与承载：dock 的「查看变更」不再切换内联面板，而是 publish 一个打开请求；新增的 shell.overlay 条目（root 作用域 list 槽位）订阅并渲染全屏视图。两者经 apply 闭包内的共享 observable 连接，与 ui-file-browser 同构（index.ts:131-145 的请求源、:205-215 的 overlay 注册）——这是仓库既有的跨作用域触发方式，不引入新机制。

D2 覆盖层形态：复用 Modal headless 模式（Modal.tsx:41-85），由本包 CSS 给出与文件浏览器一致的框架尺寸 min(1180px,94vw)/min(820px,92vh)（FileBrowserModal.module.css:13-21）；头部为路径 + +/- 统计 + 关闭，正文独立滚动，底部差异跳转条。选 headless 是因为 diff 需要自有的头部布局，默认三件套容不下。

D3 并排渲染（核心算法）：把 structuredPatch 的行序列折叠成 [left,right] 行对——相邻连续 - 行与连续 + 行按序配对，第 i 删对第 i 增占同一行；一侧多出部分补 null 渲染为空占位，故两栏始终等高、行号对齐；上下文行两侧相同；行号由 hunk 的 oldStart/newStart 递增，空位侧不编号。已本机实测：b→B、d→NEW 同行，a/c/e 对齐。

D4 折叠范围：默认展示完整文件（全屏空间已充足，折叠会再制造看不到全貌的问题）；仅当超过约 2000 行时折叠中部并保留展开控件，避免超大文件卡住浏览器。

D5 高亮：语言由路径扩展名经 language.ts 的同源映射推出，两侧都用既有 shiki 单例的 highlightLines；语法未加载时先渲染纯文本、加载后重渲染（subscribeGrammarLoaded），与 ReadBlock/CodeEditor 同取舍；未知扩展名退化为纯文本不报错。行内字符级高亮对配对成功且两侧都存在的行用 diffChars 标出增删片段，配对失败或任一侧为空位时跳过。

D6 长行与滚动：两栏各自横向 overflow，横向滚动同步（防止回环），纵向滚动由外层统一承担——两栏各自纵向滚动会导致行错位。

D7 导航：底部条提供上一处/下一处差异跳转（在 hunk 间移动并滚动到位，当前 hunk 高亮）与 +A -R · N 个文件统计；这是 git difftool 最有用的导航能力，也是当前实现完全没有的。

D8 既有能力保留：DiffBlock 继续服务会话内工具调用卡片（不删除不改语义）；withheld 三态沿用既有文案；失败文案与错误码分派复用 revisionFailureText；复制按钮保留且输出**统一格式**（-/+）而非并排视觉布局——粘贴到终端或 PR 里要仍是标准 diff（此取舍已与用户确认，用户选择统一格式）。

影响面：ui-session-changes 新增并排视图组件、请求源、CSS 与 locale 键，index.ts 追加 shell.overlay 注册，package.json 新增 diff 依赖（与 ui-trajectory 同版本 ^9.0.0）；Host 侧、Remote 契约、会话日志与录制快照均不变。

风险：对齐算法是唯一有真实逻辑复杂度的部分，必须用单测锁住边界（纯新增、纯删除、替换、行数不等、空文件、单行、末尾无换行）；字符级高亮对超大单行需设长度上限；两栏横向滚动同步需防回环；全文件展开加双栏高亮在数千行上会变慢，故 D4 的折叠上限是必要约束而非可选优化。

已确证前提：shell.overlay 声明见 ui-layout/src/client/index.ts:86 与 :130；客户端已有 shiki 单例（ui-primitives/src/markdown/highlight.ts，导出见 src/index.ts:60，用法见 ReadBlock.tsx:82）；扩展名映射见 ui-file-browser/src/client/language.ts；diff 库客户端先例见 ui-trajectory/package.json:51；structuredPatch 的 oldStart/newStart 与逐行标记、以及删增配对行为均已本机实测。
