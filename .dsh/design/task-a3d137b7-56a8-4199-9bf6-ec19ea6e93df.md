- [revision 2] ## 现状（实测，来自 ui-conversation/src/client）

- 图片是 facade 的独立扁平数组 `imageIds: DraftAttachmentId[]`，不在 Lexical 编辑器里；`addImages`/`removeImage`/`pruneImages` 直接改数组 + publish。
- 提交路径 `sendSession(session, text, imageIds, mode)` 在 `service.ts` 构造 `content = [...uploaded(images), ...text]`——图片永远排在文字之前（客户端丢弃交错顺序）。
- 附件 rail 是 `conversation.input.attachments` slot（apply.ts 声明）→ ui-attachment 的 `ComposerAttachments`（DropOverlay + AttachmentRail + ImageLightbox），intake 经 `apply.addImages(files)` → `conversation.createDraftImages` → `shell.addImages(ids)`。
- `ReferenceChipNode`（editor/chip-node.tsx）是现成模板：DecoratorNode + insert-time cache + `getTextContent()` 返回 clipboard 投影 + detect 投影用 U+FFFC。

## 决策

1. **ImageChipNode（editor/image-node.tsx）**：仿 ReferenceChipNode，持有 `__attachmentId: DraftAttachmentId` + 缩略图 display cache（previewUrl/name/width/height，创建时从 ComposerAttachment 复制）；`getTextContent()` 返回 `''`（持久化 draft 只保留 typed text，图片字节本就不过 reload）；`isInline()` true、`isKeyboardSelectable()` false；decorate 渲染缩略图 + 移除按钮 + 点击预览。detect 投影仍是 U+FFFC 一个原子字符。

2. **投影扩展（editor/projection.ts）**：`ComposerSegment.kind` 加 `'image'`；`$composerLayout` 识别 ImageChipNode 为 `pushLeaf('image', kid, ATOMIC_CHAR, '')`；`$projectComposer` 增加有序 `images` 列表（attachmentId + clipboard offset），与 occurrences 并列。

3. **InputState 用 parts 取代 imageIds（contract/input.ts）**：新增 `DraftPart = {type:'text';text} | {type:'image';attachmentId}`；`InputState.parts: readonly DraftPart[]` 从编辑器按文档顺序派生（text 节点→text part，ImageChipNode→image part）；`draft` 仍是 clipboard 投影（等于 parts 中 text 拼接）。`SessionInput.addImages/removeImage` 语义改为编辑器编辑：addImages 在 caret 插入 ImageChipNode、removeImage 移除对应 node 并释放 registry（`releaseImage`）。`pruneImages` 删除——rail 退役后 registry 释放总是伴随 chip 移除，没有"失效 node"残留可清。

4. **提交路径（service.ts sendSession + hub/facade defaultSink）**：defaultSink 从 `(text, imageIds, mode, signal)` 改为 `(parts, mode, signal)`；sendSession 按 parts 顺序映射到 PromptContentPart（text→`{type:'text'}`，image→序列化 base64→`{type:'image'}`），替换 `[...images, ...text]`。subagent 与主分支同走 parts。本地回显（beginSubmission）用 parts 的 image 段保持交错顺序。

5. **附件 rail 退役**：移除 `conversation.input.attachments` slot 声明与 ui-attachment 的 ComposerAttachments/DropOverlay 消费；保留 MessageImages（transcript 图片渲染）。移除/预览交互迁到 ImageChip 的 decorator（chip 上移除按钮 + 点击预览轻量 lightbox）；文档级拖拽 DropOverlay 与限额预检迁到 composer 的 paste/drop 处理器（InputBar）。

6. **命令提交保持现状**：CommandClaim.submit 仍收 `images: readonly SubmitImageAttachment[]`（命令的参数与图片列表语义不变，design doc 5.3 明确），故 `serializeDraftImages` 与 commandImages 通道保留。
