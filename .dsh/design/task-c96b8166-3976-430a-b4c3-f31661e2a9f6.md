- [revision 3] ## 需求

文件浏览器打开 `.md`/`.markdown`/`.html`/`.htm` 时，内容区应默认处于预览态（预览开关初始勾选），而不是先进源码编辑器。

## 设计

### D1 默认值由「预览类型是否存在」决定，落在 CodeEditor 的 state 初始化

`CodeEditor.tsx` 当前 `const [preview, setPreview] = useState(false)`，并由 `useEffect(() => { setPreview(false) }, [path])` 在路径变化时清零。改为惰性初始化：`useState(() => previewKindOfPath(path) !== undefined)`，并把路径变化的重置改为「按新路径重新求默认值」而非固定 `false`。

两类文件（文本可编辑 vs 可预览）的默认视图因此由同一条判据（扩展名）决定，与语言提示同源，不引入第二个配置面。

### D2 只读与可写入口共用同一默认，不分支

`CodeEditor` 是浏览器形态与文件形态（会话文件链接只读查看）共用的那一个组件，默认值跟随扩展名，与 `readOnly` 无关。用户已确认「所有入口统一默认预览」。

### D3 生效时机必须与文件内容同一帧，不能靠 effect 补勾

打开文件时 `FileBrowserModal` 先 `setFile(undefined)` 清空再填充，`CodeEditor` 在两次渲染中都存在（`file===undefined` 时走 notice 分支，不渲染 CodeEditor），因此实际是重新挂载，惰性初始化即可拿到正确初值。仍需保留路径变化的重新求默认值，以覆盖同一实例切换路径的情形，并避免出现「先画一帧源码再跳到预览」的闪烁。

### D4 预览态仍隐藏写动作，行为不变

默认进入预览不改变既有取舍：预览期间不显示「保存」「重新加载」，取消勾选回到编辑器即拿回未保存缓冲区。用户已确认本次不额外补编辑入口。
