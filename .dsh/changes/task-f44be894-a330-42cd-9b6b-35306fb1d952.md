- [revision 11] 对已实现的导入与编辑做业务正确性自检，发现并修复四个真实缺陷（每个都先写测试证明，再修，再回归）。

**1. GitHub 来源的路径未做校验（可逃逸目标目录）**
`relativeTo` 只校验前缀，清单行 `s/../evil.md` 前缀合法、剥离后却是 `../evil.md`，会被 `join(targetPath, …)` 拼到技能目录之外——而预览里显示的正是剥离后的路径，于是「列出的文件等于落盘的文件」这条保证不成立。修法：把 `safeEntryPath` 提升为导出函数，让归档成员与仓库清单行走**同一套**校验；并在写入前再用 `contains` 复核一次落点（纵深防御，不信任内存中的暂存对象）。

**2. GitHub 来源的体积上限只校验声明值**
原先只用 contents API 返回的 `size` 判断，而 `size` 只是 API 的说法；实际下载回来的字节才是要写入的内容，谎报即可绕过单文件与合计上限。修法：下载后按 `bytes.byteLength` 重算两个上限。

**3. 导入只校验 name 不校验 description**
`description` 缺失时，发现器会直接丢弃该技能——用户会导入出一个 agent 永远看不见的技能，界面还显示正常。修法：`previewImport` 中 description 缺失即以 `import-no-skill` 拒绝。

**4. 切换工作区后编辑/导入面板仍开着**
面板里的条目属于旧工作区，切换后该条目已不在屏幕上，继续编辑或导入会作用于用户已经看不到的另一处。修法：`projectRoot` 变化时关闭编辑器与导入面板。

另外顺手确认了两条我怀疑但不成立的：fflate 的 `originalSize` 在本场景正确（探针验证 5 MiB 成员被正确报告），因此 zip 侧「解压前按声明体积拒」是有效的；`create` 表单的 `selectedRoot` 已有回退逻辑，切换工作区后不会残留失效的 rootPath。

4. **三处不可达兜底**：`file.originalSize ?? file.size`（该字段在 fflate 类型上必填）、`header[start] ?? 0`（512 字节头内偏移必然有值）、`readEntry` 中 edit 后 `block === undefined` 的死分支——前两处直接删除。
5. **`NS` 未导出**：客户端 `client/index.ts` 的字典命名空间没写成 `export const`，与同类包不一致。

**保留的 `v8 ignore`（各带具体理由）**：客户端 `commitPreview`/`confirmRemoval` 的守卫（触发控件只在面板就绪/对话框存在时渲染）、host 的 `isAbsent` 形状守卫（参数类型为 unknown）、`planGitHub` 的 `rest ?? ''`（捕获组总会参与，回退只服务于类型）、`remove` 中非 absent 的 `rm` 失败与 `readEntry` 的 readdir/readFile 竞态（都需要套件无法可移植构造的外部条件）。
