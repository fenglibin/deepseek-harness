- [revision 17] 修复用户报告的两个问题。

问题 1「用本地编辑器打开点击没有效果」，根因是路径契约错误：session.openWorkspacePath 的请求是「已做最佳努力工作区解析后的 Host 文件系统路径」（packages/api/session-controller/src/types.ts 的 SessionOpenWorkspacePathRequest），Host 侧直接把它交给平台打开器，因此相对路径会相对 Host 进程自身的 cwd 解析——打开错误文件或直接失败。我此前传的是工作区相对路径（如 src/main.ts）。ui-chat 的既有 opener 是正确范本：先 resolveWorkspacePath(cwd, path) 再调用。
另一处叠加缺陷：失败时我执行 publish(undefined)，静默关闭了整个对话框，于是用户看到的就是「点了没反应」。
修法：openInDesktop 先按当前请求的 workspaceId 从 ctx.workspaces 快照取工作区根，经 resolveWorkspacePath 重定基为 Host 绝对路径再调用；结果改为返回失败消息而不是替换/关闭请求——替换请求会丢弃用户正在看的文件。失败消息渲染在工具栏正下方的一行 alert（新增 locale key content.openLocalFailed），文件内容保持在屏幕上。工具栏、binary 臂、too-large 臂三处调用点共用一个 openLocal 处理函数。

问题 2「关闭按钮应放到顶部最右边」：根因是 margin-left: auto 挂在 toolbarActions 上，而该 span 只在浏览模式渲染，文件模式下没有元素右推关闭按钮，于是它紧跟在「用本地编辑器打开」之后。
修法：新增 .toolbarEnd 作为始终渲染的右侧组并承载 margin-left: auto；新建按钮移入该组（它们依赖目录树，仍按 !fileView 渲染），关闭按钮成为该组最后一个子元素，因此两种模式下都占据最右位置。.toolbarActions 去掉 margin-left: auto。

关于 inject：同时把 remote.session 补进 ui-file-browser 的 inject 声明。经查证这**不是**问题 1 的根因——命名空间各自是名为 remote.<namespace> 的独立 Cordis service（packages/api/gateway/src/client/index.ts 的 createNamespace 与 remoteServiceKey），ctx.remote.session 经服务键解析、不受 inject 门控；测试替身 TestRemote 也只做 ctx.provide 而不门控属性访问，因此无法复现该假设。补齐声明是按「为已声明的注入保留 ctx.<name>」的规范更正，且注释如实写明理由。
