- [revision 4] 深度自检修复：3 个真实缺陷 + 若干正确性问题，全部以可执行探针先确证、后修复、再回归。

【阻断级】sessionFileRevisions Remote 命名空间从未挂载。
packages/api/remotes/src/client/index.ts 的 apply() 用 ctx.remote.$mount(contribution) 逐个挂载命名空间，目录里既没有该包的 import，contribution 列表里也没有它；全仓该 /remote 出口的唯一引用是 ui-session-changes 的 `import type {}`（运行时擦除）。后果：ctx.remote.sessionFileRevisions 为 undefined，而 remoteVerbs() 直接返回对象不判缺席，dock 会显示「查看变更/全部撤销」却在点击时抛 TypeError——整条功能不可用，且违反 spec「未装配修订捕获」要求的控件隐藏。
修复：引入并挂载该 contribution；package.json 补依赖；tsconfig.client.json 补项目引用；tsconfig.base.json 补 /remote 手写映射（生成器只管标记区内条目）；remoteVerbs() 补缺席判定。node 实测该出口现可解析出 sessionFileRevisions/{list,diff,revert}。

【数据丢失级】write 的 before=null 被无条件当作「会话新建」。
fs-local 对已达 diffBasisMaxBytes（默认 10MiB）、二进制、非 UTF-8 或不可读的文件覆写时，readTextForDiff 返回 null 并写入结果的 before 字段，与真正的 create 在结果里完全同形。原 captureMutation 只按 typeof before 归类，revertOne 见 baseline===null 即走 rm 分支——会删除一个本次会话并未创建的文件。
修复：以 write 输出 schema 自带的 operation:'create' 为唯一判据，引入 BaselineOrigin 三态（existing/absent/unknown）。只有 absent 允许删除；unknown 在 revert 报 conflict、在 diff 报 withheld:'baseline-missing'、在 UI 明说「无法预览也无法撤销」。foldMutation 另加保护：更晚的 unknown 捕获不得抹掉更早可用基线。

【正确性】跨会话 seq 不可比。
seq 是会话本地的（Session.seq === log.length），子代理经 childSessionMeta 以 parentSession+seedLength 从父日志 fork，其 seq 从继承长度起算。原 mergeRevisions/foldMutation 直接比裸 seq：探针实测「父 seq=100 写 base→mid、子 seq=50 事后写 mid→final」得到 baseline=mid/endState=mid，该文件的会话改动整体消失（空 diff 且撤销无效）。
修复：引入 RevisionOrder{session,at,seq} 与 compareOrder——同会话内以 seq 为准（保持折叠与到达顺序无关），跨会话以结算时刻为准，同刻同会话外以 session id 保证确定性全序。

【语义收敛】全部撤销改由宿主按权威完整集合执行（省略 path），不再由客户端传可能不完整的路径子集；这也让「已接受但仍在会话改动中」的文件被正确覆盖。

【契约清理】删除无消费者的 DEFAULT_DISPLAY_MAX_BYTES（与 API 侧重复定义）、RevertOutcome/FileRevisionSummary/RevisionSize；api 侧 oversized:boolean 改为 withheld:'oversized'|'baseline-missing'|null 以区分两种无预览原因；RevisionDiffPanel 的伪造 entry（added/removed 恒为 0）改为 path+fileCount 真实入参；修复 accept-store.ts 描述不存在参数的悬空 @param verbs；新增 locale key diff.baselineMissing。

【文档】两个新包 README 同步 origin/withheld/firstOrder/lastOrder 契约与「未捕获基线」新语义；修好其缺失的 TOC 锚点与通篇硬换行（md-wrap 该项从 24 处降至 0）；api README 补记客户端装配必须挂载 /remote 贡献。

【验证】相关四包 122 个测试全绿（新增 6 个回归用例：大文件覆写不被删除、真新建仍为 absent、 withheld 覆写不被读作 create、跨会话按时刻合并、无基线不可预览、origin 合并保真）；类型检查通过；model-experience / limitations / cordis-config / client-ui-i18n / md-wrap 在改动面内全部干净。doc-refs(1)、package-paths(6)、package-dependencies(3) 的其余失败经干净树对比确认为既有问题，不在本次改动面内。
