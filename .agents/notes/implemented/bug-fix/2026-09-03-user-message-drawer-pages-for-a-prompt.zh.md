# Agent Note: 用户消息抽屉向前翻页，直到窗口内出现一条提示词

Status: implemented

[English](2026-09-03-user-message-drawer-pages-for-a-prompt.md) | 中文

## Problem

`UserTurnPanel` 只列出窗口内携带 `user` 节点的已加载轮次，一条都没有时返回 `null`。历史分页的切分点位于倒数第 50 条 append-surface 消息的 group start，而这个 group start 是 Assistant 消息自身的 source 区间，并非轮次边界，因此当一个会话的最新轮次很长时，打开的窗口内只有 Assistant 产出、没有用户提示词。抽屉会一直隐藏，直到读者手动向前翻页到足以让一条用户消息进入窗口。

点击一条所在行尚未渲染的条目同样毫无反应：`navigateToTurn` 只在 DOM 中查找该行，未命中就静默返回。

## Decision

由 ChatView 自己驱动历史加载，不改动 Host、协议或 projection。当轨道上存在轮次却没有任何一条携带提示词、并且仍有更早历史时，视图会通过**加载更早**按钮所用的同一条锚定路径请求上一页，该路径会在页面从上方进入时保持读者位置不变。轨道为空时不发起请求：此时什么都没加载，也就没有需要纠正的切分。

点击一条所在行缺失的条目会把该条目记为待定目标并请求一页。落地的前置页若渲染出该目标，则通过 `settleAt`（直接跳转所用的同一例程）把滚动位置落到该行；若没有渲染出来，则继续翻页。两条路径都在历史耗尽时停止。

## Alternatives considered

**抽屉照常显示，只是列表为空。** 否决：读数为零的徽标和空面板没有给读者任何可操作的信息，而且这个计数会误报一个窗口上方确实存在用户消息的会话。

**向 Host 查询最新的用户轮次，或新增一个 projection。** 否决：这会把一个 Chat 呈现层需求压到 Session 协议和持久化 projection 上，让日志的每个消费方为一个抽屉买单。

**取消窗口分页，让切分点始终落在轮次边界。** 否决：它会为所有消费方改变分页契约，并且可能把无界的历史量拉进第一页；而所报告的场景只是一个很长的轮次。

**给自动翻页设定固定的页数上限。** 否决：该循环本来就在 `hasMore` 结束时终止，而上限会让任何超过该上限的轮次重新暴露同一个 bug，同时还引入一个并非随部署变化的配置项。

## Consequences

打开一个最新轮次填满窗口的会话时，现在会加载更早的分页直到出现一条用户提示词；代价是该次打开多出一到多次分页请求，而读者位置保持不变。任何位置都没有用户提示词的会话会一直翻到历史开头，且不显示抽屉。当轨道条目所在行缺失时，导航不再静默失败；直接跳转与翻页后落地共用同一例程，因此两者不会各自漂移。
