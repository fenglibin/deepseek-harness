# Agent Note: 响应语言指令改用中文书写

Status: implemented

## Problem

`zh` 响应语言指令的任务是约束模型用中文输出，而它本身是用英文写的。模型要把一段英文约束映射成中文输出行为，中间多了一层语言转换；而在 `auto` 模式下，读者还得在英文文本里辨认"这条指令只针对中文"。

指令文本是模型可见内容，它的书写语言因此是一个独立于机制的设计选择——段落位置、解析规则、空文本放弃输出都不受影响。

## Decision

`DIRECTIVES.zh` 的文本改为中文书写，约束逐条保留：正文用中文、模型自己撰写的注释用中文、代码标记与既有注释原文保留、复现原文时不切换到英文、用户用英文输入时仍保持中文。

`en` 与 `off` 的语义不变：两者都不注册段落，`en` 仍是部署方记录的固定选择，因此这次改动没有引入对侧的英文指令文本。

## Alternatives considered

**保持英文书写。** 否决：用户明确要求改用中文；用目标语言书写语言指令也更自洽——约束与目标处在同一种语言里，模型不必先做一次语言映射。

**中英双语并列，让模型任选。** 否决：同一组约束写两遍会成倍加长段落，且模型可能把它们当成两组独立要求分别执行，或在两段之间做不必要的取舍。

**先做中英对照验证再决定。** 否决：本次按用户选择直接上线观察。对照实验要在真实会话里重复采样并人工判定注释语言，成本高于"上线后观察、变差再回退"的路径。

**把指令拆成"回复语言"与"注释语言"两段。** 否决：当前只有一种语言需要指令，拆段会让集中顺序表、测试与 README 都多出一个维度，而收益要等到有第二种语言时才出现。

## Consequences

指令字符数从约 900 降到约 300，token 开销相应下降；段落位置（`RESPONSE_LANGUAGE`，−950）、解析规则与空文本放弃输出的机制都不变。

这是仓库里第一段非英文的 prompt 文本。其余 prompt 段落仍是英文，因此后续新增 prompt 文本时要有意识地判断书写语言，而不是默认英文；判断依据是这段文本约束的是哪种输出。

没有实测证据表明中文书写的指令遵循率更高，这是一个靠上线观察检验的假设。若模型行为变差，回退方式是恢复英文文本，同时回退 README 围栏块与测试断言。

## Testing

- `response-language.spec.ts` 的两条 `directiveText` 用例改断言中文短语（`不要切换成英文`、`你自己撰写的注释也用中文` 等），整个包 19/19 通过。
- `loader.spec.ts` 比对 `directiveText('zh')` 而非硬编码文本，不受影响。
- `snapshots/` 的 expected 输出不含 zh 指令文本，`test:snapshot` 不受影响。
