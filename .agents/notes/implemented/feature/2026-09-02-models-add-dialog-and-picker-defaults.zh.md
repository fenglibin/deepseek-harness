# Agent Note: 一个添加模型对话框，以及以提供方已配置模型为起点的选择器

Status: implemented

[English](2026-09-02-models-add-dialog-and-picker-defaults.md) | 中文

## Problem

模型设置页为同一个意图提供了两个按钮。**添加提供方**从适配器已安装目录里挑一条路由；**添加自定义提供方**声明一条目录没有的路由。两者的目的都是获得一个提供方，差别只在于路由的词汇来自哪里——但操作者必须先给自己的情况分类，而面对公司网关的用户必须认出*第二个*按钮才是自己的。两个按钮各自在行列表下方展开一张内联卡片，于是用户滚动时页面不断变长，两张卡片还重复了同样的页脚、同样的关闭语义和同样的 provider-card 席位分发。

**获取可用模型**的选择器还有一处更安静的缺陷：无论新增还是编辑，它打开时都勾选发现到的每一个模型。对于一个已配置了四十个已发现模型中三个的提供方，采纳选择器意味着取消勾选三十七行，或者接受一次把四十个模型全部重新写入的写操作——一个读作「添加我勾选的模型」的入口，悄然变成了「保留全部」。

## Decision

**单个添加模型 / Add model 按钮打开一个对话框，两条路径都在其中。** 选择步骤展示提供方 `<select>`（休眠目录行：尚未配置且拥有 settings 地址），其下方是**或手动输入 API 地址**输入框与**使用此地址**按钮。挑选一条路由会在对话框内展开该路由的普通提供方编辑卡片，与已保存行展开的编辑器是同一张；键入地址则展开手工声明的创建卡片，并以去除首尾空白后的该地址作为其 base URL，因此端点不会被问两遍。**返回**可从任一张卡片回到选择步骤；没有可添加的行时，选择步骤会说明适配器目录中的提供方都已添加。当目录无行可添加、且没有可用于手工声明路由的协议时，该按钮禁用。

**已展开的卡片从全部合并行中解析自己那一行，而不是从可添加集合中解析。** 否则草稿进行中把该路由配置好的一次刷新——凭据重试路径，或另一位操作者——会在用户正在输入时把卡片从对话框里拆掉。

**对话框仍然为所选路由分发 `settings.models.provider-card`。** 该席位以行的 settings namespace 为键，因此以某适配器家族的 namespace 注册一次，就能像收到已保存行的卡片一样收到新增卡片；新增草稿正是操作者手握该提供方、却还没有密钥的时刻，这也正是该席位最有价值的时刻。手工声明的卡片在保存前仍然不分发，因为它还没有可按键的目录行。

**选择器的默认勾选随场景而变。** 编辑某个提供方行时，选择器只勾选该提供方已配置的模型，因此采纳它会保留已存储的模型并追加新勾选的模型。提供方尚无任何模型时（新增场景），则勾选发现到的每一个模型，因此新增提供方仍然是一次动作而非四十次。筛选依旧只缩小显示的行、从不缩小已勾选的集合，并且在点击**添加所选**之前不写入任何内容。

## Alternatives considered

**保留两个按钮，只改标签。** 否决：问题从来不在标签。两个入口会强迫操作者回答一个页面能自己回答的问题——他想要的路由是否在已安装目录里——而只要两条路径位于同一个按钮之后，这个问题就不需要问。

**合并为一张带内部模式切换的内联卡片。** 否决：它保留了会让页面变长的卡片，而模式切换是在一个已经索要端点、协议和模型的界面上多问一个问题。覆盖在分区之上的对话框表明「添加提供方」是一个有界步骤，并让两条路径获得同等地位；行列表下方的卡片则会与它即将创建的行争夺注意力。

**先问进入方式，之后只展示所选卡片。** 否决：输入了地址之后又想改用目录路由的操作者，必须先退出再重新进入。选择步骤通过**返回**保持可达，因此一次猜错只花费一次点击，而不是重新开始。

**选择器打开时全部不勾选（两种场景都不勾）。** 否决：它让最常见的新增场景——把该端点提供的模型都拿进来——变成四十次点击，而**获取可用模型**存在的意义正是一次回答「这个端点有哪些模型？」。

**选择器打开时全部勾选（原行为）。** 否决：对尚无模型的提供方正确，对已有模型的提供方则是错的。以提供方自身已配置的集合作为默认值，是唯一在两种场景下都意味着「添加我勾选的模型」的默认值。

**让选择器把整个模型列表作为替换写入。** 否决：它会把一个标注为**添加所选**的入口变成一次破坏性写入；目录里少了一个模型的提供方会静默丢掉那一行。选择器仍然只做添加；删除某一行仍然由该行自己的删除动作负责。

## Consequences

分区少了一个按钮、多了一个对话框，新增流程不再与行列表争夺纵向空间；代价是设置对话框之下又多了一层模态嵌套，`Modal` 原语已经通过其 portal 支持这一点。

**添加模型**现在命名的是分区入口，因此模型目录自己的行按钮改名为**手动添加 / Add manually**——即它所执行的动作，与从端点填充行的**获取可用模型**按钮并列。手工声明卡片被填入的 base URL 是可编辑的，因为操作者为了进入而输入的地址是他最可能想要的地址，而不是页面拥有的值。

选择器在编辑场景下的默认值是一个回访用户能感知到的行为变化：对已配置的提供方点击**获取可用模型**，预勾选的行比以往更少。这正是意图所在——预勾选的集合就是已存储的集合——而清空它仍然只需要一次**取消全选**。
