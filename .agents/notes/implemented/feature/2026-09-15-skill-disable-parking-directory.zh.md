# Agent Note: 技能设置页的作用域分栏、停放目录、文件编辑与导入

Status: implemented

## 问题

技能管理面落地后，设置 →「技能」是一列平铺的表单与分组列表：新建表单常驻首屏，每个被扫描的根各自成段，条目行把名称、描述与四类标记挤在一行。用起来有三处具体缺口。

其一，发现器有六个根，界面把它们全平铺出来，而读者心里只有三件事——我自己的、这个 DSH 安装的、这个工作区的。根路径与 rank 是发现器的内部词汇，泄漏到了读者眼前。

其二，技能没有整体开关。frontmatter 有 `disable-model-invocation` 与 `user-invocable`，但它们表达的是「谁能调用」，不是「这个技能此刻是否生效」；而且它们要写进技能文件，读者改一次就永久留在文件里。

其三，编辑只能改 SKILL.md 的 frontmatter 与正文，目录包里的 `references/`、`scripts/`、`assets/` 没有入口；导入只接受 URL，拿不到一个已经下载到本地的压缩包。其四，导入把来源表单、预览与写入挤在同一个弹窗里：预览区被表单挤窄，底部同一个按钮位置先后承担「预览」和「写入」两个动作，而读者只想直接导入时也不得不先看一遍预览。

## 决策

### 作用域三分类由客户端按 `source` 映射

三个页签只呈现三个来源集合：全局是 `user-agents`（`<agentsHome>/skills`），应用是 `user-dsh`（`<dshHome>/skills`），工作区是 `project-dsh` 与 `project-agents`（项目根下的 `.dsh/skills` 与 `.agents/skills`）。`custom` 与 `bundled` 根不进入任何页签。

映射写在客户端而不让 Host 新增 `scope` 字段：`source` 已经是发现器的稳定契约，而「这三个来源归到哪一屏」是呈现决策。把分组写进 wire 词汇，会让 Host 承担一份它不拥有的知识，且界面每调整一次分组都要改 Host。

不展示的两类根是有意的：`bundled` 随部署交付且只读，`custom` 属于部署方配置而非读者；把它们塞进某个页签会让那个页签的作用域名不副实。

### 启用状态由同根的 `.disabled/` 目录承载

禁用把条目移入同一个根下的 `.disabled/`，启用移回。目录包移动整个 `<name>/` 目录，扁平技能移动 `<name>.md`。

发现器只解析根的一层直接子项：目录项要求 `<dir>/SKILL.md` 存在，文件项要求 `.md` 结尾。`.disabled/` 下既没有 `<root>/.disabled/SKILL.md`，它的成员也不是根的直接子项，因此禁用即刻从模型目录与 `/` 命令目录消失。

同根内 `rename` 是原子的，技能文件一个字节都不改，恢复即回到原位。移动本身触发 watcher：禁用产生原路径的 `unlinkDir`，启用产生新路径的 `addDir`，两者都落在 `depth: 1` 的观察面内，所以缓存失效不需要额外通道——这是这套约定最省事的一点，也是它优于「写状态」方案的根因。

发现器补了一条对 `.disabled` 的显式跳过。当前扫描逻辑恰好也扫不到，但那是「它下面没有 SKILL.md」的巧合；显式跳过把「停放目录永远不是技能」写成提供方的契约，顺带省掉每个根每次发现的一次多余 stat。

管理面额外扫描 `.disabled/`，把其中的条目标记为 `enabled: false` 并排在同一张表里。禁用后条目若从列表消失，读者就没有恢复入口。

### 文件编辑走独立的一组 Remote 方法

新增 `listFiles`、`readFile`、`writeFile`，不复用只服务 frontmatter 表单的 `read`：后者返回解析后的字段，而编辑器要的是文件的原文。

约束有四条。解析后的绝对路径必须落在条目的文件根内——扁平技能的「文件根」是它与所有同级技能共享的目录，所以它只拥有寻址它的那一个文件。文件数与递归深度设上限，且不跟随符号链接，避免一个自指链接或病态嵌套把渲染一棵树变成无界扫描。单文件超限或内容含 NUL 字节判为只读并**扣留正文**而不是截断返回，因为交回半截正文等于邀请一次会毁掉后半段的保存。写入目标为条目入口文件时先校验 frontmatter 的 `name` 与 `description`：入口文件是目录包的 `SKILL.md` 或扁平技能唯一的那一个文件，按文件名判定会漏掉后者。发现器会静默丢弃不合法条目，界面不能把读者的技能写成一个模型永远看不到的文件。

### 编辑器是透明 textarea 叠加高亮层

底层 `<pre>` 渲染 `highlightLines` 的逐行 span，上层 `<textarea>` 文字透明、光标可见，两层共用字体、行高与内边距，滚动由 textarea 同步到底层。textarea 关掉软换行：折行的一行在两层里占的行数不同，一旦折行后续每一行都会错位。

不引入编辑器依赖。`ui-primitives` 已经持有仓库唯一的语法高亮器，`highlightLines` 正好输出逐行 span；`LANG_ALIASES` 的键本身就是文件扩展名，所以语言提示直接取扩展名，不需要第二份映射表。

### 上传与 URL 导入共用同一段解包

`import/source.ts` 把「下载」与「解包内存字节」拆开，上传路径把浏览器传来的规范 base64 字节交给同一段解包与同一套完整性检查。理由是预览的诚实性：读者批准的清单必须就是落盘清单，两条来源各走一套解包就会有两份会漂移的保证。

上传体积上限独立于解包上限，因为 base64 会放大约三分之一；上限在客户端也查一次，纯粹为了不让超限文件先编码再走一个来回，权威仍在 Host。

### 导入的预览与保存是两个动作

导入表单的底部固定三个按钮——取消、预览、保存，不再随状态切换身份。预览在表单之上叠加一个独立的只读弹窗，与编辑弹窗同构：左侧文件树、右侧高亮正文，宽度也取编辑弹窗的 `min(1100px, 92vw)`；差别只有恒定的 `editable={false}`，因为落盘的就是压缩包里的字节，预览里没有可改的东西。

预览独立成弹窗而不是留在表单里的内联区域，理由是两件事的判断不同：填来源与目标根是一件事，逐文件判断将写入什么是另一件事。内联的做法把两者压进一个 680px 的弹窗，预览区被挤窄，而底部同一个位置先后承担两个动作。拆开之后，关闭预览回到表单，已填的来源与目标根都还在。

表单关闭时受一道 `inspectingRef` 守卫：两个弹窗都监听 document 的 `keydown`，一次 Escape 会到达两个处理器，守卫让栈底的表单只在预览不在时才响应。用 ref 而非 state，是为了不受两个弹窗监听器注册先后顺序的影响。

「保存」把解析与写入连做，不为第二次动作再解析一遍：写入只接受预览标识，而标识只能由解析产生，因此保存必然是两步，只是中间产物不展示。已解析且来源未变时复用同一个标识，避免白占一个预览槽位。解析结果带 `replaces` 时不发起写入，就地显示本地化的拒绝文案——Host 已在预览阶段给出这个结论，再打一次注定被 `skill-admin/entry-exists` 拒绝的调用没有收益；Host 仍是裁决者，它在写入处的检查一行未动。

## 曾考虑的替代方案

**在技能目录里放标记文件**（如 `<name>/.disabled`）。不予采纳：扁平技能没有自己的目录，两种形态无法对等表达；而且每个技能每次发现都要多一次 stat。

**在 frontmatter 里加 `enabled` 键。** 不予采纳：要求 `dsh-skill` 与 `dsh-skill-filesystem` 同时认这个键，而键会随技能文件被复制、被导入、被分享，语义脱离这台部署——一个从别人那里拷来的技能不该带着「在我这儿是禁用的」。

**把禁用清单写进 DSH 配置。** 不予采纳：技能文件不动，但状态脱离技能本体，换机器或重装即丢失，而技能本身是随目录走的。

**沿用 frontmatter 的两个调用开关充当整体开关。** 不予采纳：它们同时是「谁能调用」的细粒度策略，拿它们当总开关会覆盖读者的原意，且恢复时无从知道原来的组合是什么。

**引入编辑器依赖（CodeMirror 一类）。** 未采纳：仓库已有唯一的高亮器，逐行 span 的接口正好够用，而引入第二个解析与渲染栈只为省下叠加层的对齐样式。

**让上传走一条独立的 HTTP 端点。** 不予采纳：Remote 已经是既有的受信通道，二进制以规范 base64 承载有 `dsh-attachment` 的准入先例，为一次上传另开一条不经同一校验的路径得不偿失。

**把预览留在导入表单内联，只把底部按钮拆成两个。** 不予采纳：这样省掉一个弹窗，但表单要继续容纳文件树与正文两栏，读者为了看清预览仍要在一个为表单设计的宽度里看代码，而两件事的判断依旧挤在同一屏。

**在预览弹窗内再放一个写入按钮。** 不予采纳：写入会因此有两个入口，两处都要处理忙态与失败，而预览的职责是看；关闭预览回到表单再点保存，代价只是一次点击。

## 后果

收益是页面只讲读者关心的三件事，技能有了可逆的整体开关，编辑器覆盖目录包里的每个文件，导入接受本地压缩包，且导入的「看一眼」与「写进去」是两个各自独立、都从表单出发的动作。

代价有四处。其一，`.disabled` 是管理面与发现器之间的约定，第三方工具不认识它——它不会被读成技能，但也不会被别的工具自动跳过。其二，条目身份仍是绝对路径，切换启用状态后同一条技能的身份串就变了，调用方不能跨写操作缓存 `entryId`。其三，编辑器不做二进制编辑，图片等资源只列出、只读，替换它们仍要回到文件系统。其四，`custom` 与 `bundled` 根在这页看不到，需要时得按来源另开入口。

不涉及 `SessionEventMap`、会话日志或面向模型的目录渲染，因此两台 SDK 的期望输出与录制快照不受影响。

## Deferred

上传的体积上限是写死的安全界而非可配置项——它与解包上限一样属于不可信输入的边界。编辑器的语法高亮对未收录的扩展名降级为纯文本，扩展语言集要动 `ui-primitives` 的懒加载表。文件名的新建、删除与重命名不在文件夹浏览器内，仍要回到文件系统。
