# Agent Note: 文件浏览器内容区的 Markdown 与 HTML 预览

Status: implemented

## 问题

文件浏览器的内容区把每个文本文件都当作源码。[文件浏览器与工作区行菜单扩展点](../architecture/2026-09-16-workspace-file-browser.zh.md)当初的判据是「文本可编辑、图片可查看」，而 Markdown 与 HTML 恰好是既不是图片、又不该只看源码的两类文件：`.md` 里的表格、流程与公式读不出来，`.html` 页面本身长什么样也看不到。

同一个内容区同时服务两个入口——工作区行菜单打开的浏览器形态，与[会话文件链接的只读查看](../architecture/2026-09-16-session-file-readonly-viewer.zh.md)打开的文件形态——两者渲染的都是 `CodeEditor`。所以这项能力只能落在 `CodeEditor` 上：放在弹层里会漏掉另一个入口，放在第二个组件里会把工具栏、保存状态与冲突横幅各复制一份。

## 决策

### 预览类型由扩展名决定，是 Client 侧的呈现事实

新增 `preview.ts` 的 `previewKindOfPath(path)`，与既有 `languageOfPath` 并列：一个决定怎么呈现，一个决定怎么着色。`.md`/`.markdown` 归为 markdown，`.html`/`.htm` 归为 html，其余返回 `undefined`——不可预览的文件不渲染预览控件，而不是拿到一个「纯文本预览」臂。Host 只回答字节，呈现方式属于 Client，与语言提示同一条理由。

### 预览是切换，不是分栏，且可预览文件默认进入预览

预览开关勾选后内容区由编辑器切换为预览，取消勾选回到编辑器。分栏会同时压缩源码与预览的宽度，而对话框左侧已经有一列目录树，再切一刀后两侧都太窄。

**默认值是「打开可预览文件即预览」。** 打开一份 Markdown 或 HTML，要看的本来就是渲染结果——`.md` 的判据就是「表格、流程与公式读不出来」，那么把它先当成源码呈现一次，是把操作者导入一个他并不想看的视图。默认值由扩展名决定（`previewKindOfPath` 有值即为 `true`），与语言提示同一条判据，不引入第二个配置面；只读形态与可写形态共用这一默认，因为它约束的是阅读而不是写入。

默认值在渲染期求值而非由 effect 事后纠正：`useState(() => previewKind !== undefined)` 让首帧就是渲染结果，避免「先画一帧源码再跳到预览」。

默认值**只描述「打开」这个动作**。切换文件按新文件重新取默认值；而重新加载当前文件留在操作者所在的视图里——他要求的是把磁盘内容取回当前视图，此时若按默认值把他拉回预览，就与「打开另一个文件」混为一谈。为此 `FileBrowserModal` 的读取拆成 `readFile(path, keepOpen)`：打开会先清空当前文件（导致 `CodeEditor` 重挂载并重新取默认值），重新加载则保留它。

两种视图**共用同一份缓冲区**：预览渲染的是缓冲区当前内容，包括未保存的修改；取消勾选时编辑器里的内容从未被替换过，因此不需要任何回写动作，也不存在「预览期间改了但没同步」这种状态。代价是预览期间不提供保存与重新加载——它们是编辑动作，回到编辑器即可。

切换而不是分栏也决定了预览态隐藏写动作：一个仍然点得到「保存」的渲染结果会让人以为保存的是渲染结果。

### Markdown 复用既有的 `MarkdownText` 管线

`ui-primitives` 的 `MarkdownText` 已经是本仓唯一的 Markdown 渲染器：GFM（表格、任务列表、删除线）、KaTeX 数学、mermaid 流程图、脚注，README 对话框与轨迹视图都用它。传 `diagrams: { errorLabel }` 即得到流程图渲染。

自建解析器要重新处理一整套既有规则——原始 HTML 保持字面、相对链接与不安全协议被禁用、流式与一次性渲染的一致性——而且会与那条管线漂移。因此这里只做接线，不做解析。

### HTML 用 `srcDoc` 与 `sandbox="allow-scripts"`

HTML 无法走 Markdown 管线：文件本身就是一份文档，只有浏览器自己的解析器能渲染它。内容是 `srcDoc`，框架带 `sandbox="allow-scripts"` 而不给 `allow-same-origin`，文档因此落在不透明源上——脚本仍可运行，而 `localStorage`、Cookie 与同源 `/api` 请求都不可达。这三条都在真实 Chromium 中实测过：脚本确实运行，`localStorage` 与 `document.cookie` 抛 `SecurityError`，`window.origin` 为 `null`。

**框架的底色是文档自己的白纸，不是宿主的主题表面。** 这是渲染检查抓到的缺陷：产出 HTML 通常不声明任何颜色，UA 样式表因此给它黑字；深色主题下若把框架填成主题的深色 surface，黑字就压在深底上不可读。初版正是这么做的（`--dsw-alias-bg-layer-1`），在深色主题的实测截图中肉眼可见。文档就该保持文档的底色，周围的界面仍然表明当前主题。

否决**完全禁脚本**：产出 HTML 常靠脚本渲染自己，而本仓已有实测记录（[从 web UI 打开产出的文件](2026-07-31-web-workspace-file-links.zh.md)），报告者工作区四份产物有两份在禁脚本的沙箱下是死页面，并且因为渲染得完美无缺，这种破坏是看不见的。

否决**`iframe src` 指向 Host 提供的路由**：那正是同一条记录里实测把 `settings.describe` 与 `session.list` 打成 `200` 的路径，而且要为它新增一条 Host 路由及其生命周期。`srcDoc` 由客户端已在内存里的缓冲区提供，不引入任何新的 Host 面。

代价是文档内相对的 `<img>`、`<link>`、`<script src>` 按宿主页面地址解析，因此加载不到同目录的同级文件；只有绝对地址或内联内容生效。这是内容即文本的必然结果，记在包 README 的限制里。

### 尺寸调整留在本包作用域内

工具栏那一行是密集控件行，共享原子的默认几何不合适：搜索框用 `FileBrowserModal.module.css` 里的 `.search` 容器把它从 32px/14px 收到 26px/13px，内容区的「重新加载」「保存」改用 `Button` 已有的 `size="sm"`（28px/12px，正是「已保存」的字号）。

否决**改 `ui-primitives` 的 `Input` 与 `Button` 默认值**：它们是全仓共享原子，改默认值会外溢到所有消费者；本包只需要自己那一行不同。

## 考虑过的备选方案

**在弹层里做预览，而不是在 `CodeEditor` 里。** 内容区的工具栏、保存状态与冲突横幅都归 `CodeEditor`，在弹层里做就要把这三样各复制一份；而文件形态又是另一个入口，两处会各自漂移。

**新增一个独立的预览组件替换整个内容区。** 与上一条同因：`CodeEditor` 是两种形态共用的那一个组件，第二个组件意味着第二份工具栏与第二份状态陈述。

**分栏同时显示源码与预览。** 对话框左侧已有目录树，再切一刀后两侧都太窄；预览是阅读，读的时候不需要源码并排。

**完全禁止 HTML 预览里的脚本。** 产出 HTML 常靠脚本渲染自己，而本仓已有实测记录显示禁脚本会让多数产出页面变成死页面，并且因为渲染得完美无缺，破坏看不见。

**用 `iframe src` 指向 Host 提供的路由来渲染 HTML。** 那正是同一份记录里实测导致 `/api` 数据泄露的路径，且要为它新增一条 Host 路由及其生命周期；`srcDoc` 用客户端已在内存里的缓冲区即可。

**自建 Markdown 解析器。** `MarkdownText` 已覆盖 GFM、KaTeX 与 mermaid，并已处理原始 HTML 保持字面、不安全协议禁用、流式与一次性渲染一致等规则；第二份解析器只会与它漂移。

## 后果

- 浏览器形态与文件形态同时获得预览，因为两者渲染同一个 `CodeEditor`；只读形态也提供预览开关——只读约束的是写入，不是阅读。
- 预览不需要新的 Host 协议、会话事件或模型可见输入，因此不影响会话日志与 KV 缓存。
- 预览类型只由扩展名决定，没有手动指定类型的入口；没有扩展名的文件不提供预览。
